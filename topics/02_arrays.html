Arrays, Hashing and Searching — Pattern Guide

One consolidated guide to the array family: two pointers, sliding window, prefix sums, Kadane, hashing, partitioning, binary search and selection. Every pattern has the intuition, an animation you can step through, code in Java and Python, complexity, traps and a ladder of LeetCode problems.

How to use this page

For each section: read Detect and Intuition, play the animation, then try to write the skeleton from memory before opening the code. Finish by solving the problem ladder in order.

The mindset

Most array problems are about avoiding the O(n²) brute force by exploiting structure: sortedness, a running aggregate, a hash of what you have seen, or a window you grow and shrink. The workhorses are two pointers, sliding window, prefix sum and hashing. Binary search adds O(log n) lookups when the data (or the answer space) is monotonic.

Ask these questions on every problem:

  • Is it (or can it be) sorted? → two pointers or binary search become available.
  • Do I need information about a contiguous range? → sliding window or prefix sum.
  • Do I need "have I seen this / how many times"? → hashing.
  • Can I check a guessed answer quickly? → binary search on the answer.

Two Pointers

🔥 Frequently asked
When to useA sorted array or a string where two indices moving toward (or along with) each other replace a nested loop.
Detect itsorted input · "pair/triplet with target sum" · "remove duplicates in place" · palindrome check · "reverse in place" · "partition so that…".
Intuition

Picture two people walking toward each other along a sorted number line. If their combined value is too small, only the left person stepping right can help; if too large, only the right person stepping left can help. Every step permanently rules out one element, so you never look back.

Brute force → optimised

Check every pair with two loops: O(n²). Sorting gives each pointer a direction to move, so one pass of n steps is enough: O(n).

Core idea

Two indices, usually l and r, move based on a comparison. The sorted order guarantees that discarding one end can never throw away the answer.

How it works
  1. l = 0, r = n-1.
  2. Compare a[l] + a[r] with the target.
  3. Too small → l++. Too big → r--. Equal → record and finish.

opposite ends (sorted pair sum)

int l = 0, r = n - 1;
while (l < r) {
    int sum = a[l] + a[r];
    if (sum == target) return new int[]{l + 1, r + 1};
    if (sum < target) l++; else r--;
}
return new int[]{-1, -1};
l, r = 0, len(a) - 1
while l < r:
    s = a[l] + a[r]
    if s == target:
        return [l + 1, r + 1]
    if s < target:
        l += 1
    else:
        r -= 1
return [-1, -1]
Skeleton

same direction (slow writes, fast reads) for in-place edits

int slow = 0;
for (int fast = 0; fast < n; fast++) {
    if (a[fast] != 0) a[slow++] = a[fast];   // keep non-zeros
}
while (slow < n) a[slow++] = 0;
slow = 0
for fast in range(len(a)):
    if a[fast] != 0:
        a[slow] = a[fast]
        slow += 1
for i in range(slow, len(a)):
    a[i] = 0
⏱ Complexity — O(n) time after any sort, O(1) extra space.
Traps to avoid
  • 3Sum: sort first, fix one element, skip duplicates for the fixed element and after finding a triple.
  • Opposite-end version needs sorted data; same-direction version does not.
  • Container With Most Water has no sort: you move the shorter wall because only that can raise the area.
Variants and follow-ups
  • Closest sum instead of exact (3Sum Closest): track the best difference.
  • k-Sum: recurse down to two pointers, O(n^(k-1)).
  • Palindrome with deletions: when mismatch, try skipping either side.
When NOT to use

When order cannot change and the data is not sortable for the task, or when every pair genuinely matters.

Sliding Window (Fixed)

🧊 Secondary
When to useCompute something over every contiguous window of a fixed size k.
Detect it"subarray/substring of size k" · max/min/average over windows of length k · "anagram of a pattern" (window = pattern length).
Intuition

A train of k carriages passing a platform: as the front carriage enters, the rear one leaves. You do not recount all k carriages; you add one and remove one.

Brute force → optimised

Re-sum every window: O(n·k). Updating the sum incrementally costs O(1) per step: O(n).

Core idea

Keep the window's aggregate; on each step add the entering element and subtract the leaving one.

How it works
  1. Build the first window of size k.
  2. For each next index i: add a[i], subtract a[i-k].
  3. Update the answer after each slide.

Skeleton

max sum of a window of size k

int sum = 0;
for (int i = 0; i < k; i++) sum += a[i];
int best = sum;
for (int i = k; i < n; i++) {
    sum += a[i] - a[i - k];
    best = Math.max(best, sum);
}
s = sum(a[:k])
best = s
for i in range(k, len(a)):
    s += a[i] - a[i - k]
    best = max(best, s)
⏱ Complexity — O(n) time, O(1) space (O(k) if you keep a count map or deque).
Traps to avoid
  • Off-by-one on i - k.
  • Initialise the answer from the first full window, not 0 (breaks with negatives).
  • For anagram windows compare two 26-slot count arrays, or keep a "matched characters" counter to make each step O(1).
Variants and follow-ups
  • Window maximum: a monotonic deque of indices keeps the max at the front (LC 239).
  • Counting distinct values in each window: maintain a count map.
When NOT to use

When the window size depends on a condition: that is the variable window (pattern 3).

Sliding Window (Variable)

🔥 Frequently asked
When to useFind the longest or shortest contiguous range that satisfies a condition.
Detect it"longest/shortest substring with…" · "at most K distinct" · "subarray sum ≤ S" · "smallest window containing…".
Intuition

An inchworm: the head (right) stretches forward to take in more; whenever the body becomes illegal, the tail (left) pulls in until it is legal again. Neither end ever moves backwards, so each element is added once and removed once.

Brute force → optimised

Check every (start, end) pair and validate each: O(n²) or O(n³). Because the window only ever moves forward, the total work is 2n pointer moves: O(n).

Core idea

Expand r to include elements. While the window violates the condition, advance l and undo its contribution. Record the best valid window.

How it works
  1. Move r outward, updating window state (count map, running sum).
  2. While invalid, advance l, undoing its contribution.
  3. When valid, record the answer (length or position).

Skeleton

longest valid window (template)

int l = 0, best = 0;
Map<Character, Integer> count = new HashMap<>();
for (int r = 0; r < s.length(); r++) {
    count.merge(s.charAt(r), 1, Integer::sum);
    while (count.get(s.charAt(r)) > 1) {          // window invalid
        count.merge(s.charAt(l), -1, Integer::sum);
        l++;
    }
    best = Math.max(best, r - l + 1);
}
l = best = 0
count = {}
for r, ch in enumerate(s):
    count[ch] = count.get(ch, 0) + 1
    while count[ch] > 1:                  # window invalid
        count[s[l]] -= 1
        l += 1
    best = max(best, r - l + 1)
Skeleton

shortest valid window (record while valid, shrink as far as possible)

int l = 0, sum = 0, best = Integer.MAX_VALUE;
for (int r = 0; r < n; r++) {
    sum += a[r];
    while (sum >= target) {                       // valid: try to shrink
        best = Math.min(best, r - l + 1);
        sum -= a[l++];
    }
}
return best == Integer.MAX_VALUE ? 0 : best;
l = total = 0
best = float('inf')
for r, x in enumerate(a):
    total += x
    while total >= target:                # valid: try to shrink
        best = min(best, r - l + 1)
        total -= a[l]
        l += 1
return 0 if best == float('inf') else best
⏱ Complexity — O(n) time (each element enters and leaves once), O(k) space for the window state.
Traps to avoid
  • Forgetting to undo l's contribution when shrinking.
  • Longest → update the answer after the shrink loop; shortest → update inside the loop while valid.
  • "Exactly K" = "at most K" − "at most K−1".
  • Negative numbers break shrinking (adding can reduce the sum). Use prefix sum + hash map instead.
Variants and follow-ups
  • At most K distinct / replacements: window is valid while size − maxFreq ≤ k.
  • Count subarrays: add r − l + 1 for each valid right end (LC 713).
  • Min window containing all of a pattern: keep a need count and a formed counter.
When NOT to use

When the subarray need not be contiguous, or when negatives make the validity non-monotonic.

Prefix Sum

🔥 Frequently asked
When to useMany range-sum queries, or counting subarrays whose sum hits a target.
Detect it"sum between i and j" · repeated range queries · "number of subarrays with sum = k / divisible by k" · arrays with negatives.
Intuition

Think of kilometre markers on a road. The distance between two markers is just the difference of their readings. If the reading at your current position minus an earlier reading equals k, the stretch between them is exactly k long. So ask the map: "have I seen the reading current − k before?"

Brute force → optimised

Sum every subarray: O(n²) (or O(n³)). With prefix sums each range is one subtraction; with a hash map of earlier prefixes each index is one lookup: O(n).

Core idea

pre[i] = sum of the first i elements, so sum(i..j) = pre[j+1] − pre[i]. Combine with a map prefix → count to count subarrays in one pass.

How it works
  1. Keep a running sum and a map prefix → how many times seen, seeded with {0:1}.
  2. At each index the number of valid subarrays ending here is map[sum − k].
  3. Then add the current sum to the map.

Skeleton

count subarrays summing to k

Map<Integer, Integer> seen = new HashMap<>();
seen.put(0, 1);                       // empty prefix
int sum = 0, count = 0;
for (int x : a) {
    sum += x;
    count += seen.getOrDefault(sum - k, 0);
    seen.merge(sum, 1, Integer::sum);
}
seen = {0: 1}                         # empty prefix
total = count = 0
for x in a:
    total += x
    count += seen.get(total - k, 0)
    seen[total] = seen.get(total, 0) + 1
Skeleton

static range-sum queries

int[] pre = new int[n + 1];
for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
// sum of a[i..j] inclusive
int rangeSum = pre[j + 1] - pre[i];
pre = [0] * (len(a) + 1)
for i, x in enumerate(a):
    pre[i + 1] = pre[i] + x
range_sum = pre[j + 1] - pre[i]        # a[i..j] inclusive
⏱ Complexity — O(n) time, O(n) space.
Traps to avoid
  • Seed the map with {0:1} or you miss subarrays that start at index 0.
  • Divisible-by-k: normalise the remainder with ((s % k) + k) % k in Java.
  • Prefix XOR is the same trick with XOR. For 2D use a 2D prefix with inclusion–exclusion.
  • If the array is updated between queries a static prefix goes stale: use a Fenwick or segment tree.
Variants and follow-ups
  • Longest subarray with sum k: store the first index of each prefix instead of a count.
  • Equal 0s and 1s: map 0 → −1, then longest subarray with sum 0.
  • Product except self: prefix and suffix products.
When NOT to use

When values change between queries (use BIT / segment tree), or when you only need a single sum (just loop).

Kadane's Algorithm

🧊 Secondary
When to useMaximum-sum (or product) contiguous subarray.
Detect it"maximum subarray sum/product" · contiguous segment · a running optimum that can "restart".
Intuition

You are walking and collecting money (positive) or paying tolls (negative). If your wallet balance since the start of the current run has gone negative, that history can only hurt, so drop it and start a fresh run from here.

Brute force → optimised

Try every subarray: O(n²). Observing that the best subarray ending at i is either a[i] alone or extends the best ending at i−1 gives O(n).

Core idea

cur = max(a[i], cur + a[i]) is the best subarray ending at i; best is the maximum of cur seen so far.

How it works
  1. cur = best = a[0].
  2. For each next element: cur = max(a[i], cur + a[i]).
  3. best = max(best, cur).

maximum subarray sum

int cur = a[0], best = a[0];
for (int i = 1; i < n; i++) {
    cur = Math.max(a[i], cur + a[i]);
    best = Math.max(best, cur);
}
cur = best = a[0]
for x in a[1:]:
    cur = max(x, cur + x)
    best = max(best, cur)
Skeleton

maximum product subarray (negatives flip sign: track both)

int mx = a[0], mn = a[0], best = a[0];
for (int i = 1; i < n; i++) {
    int x = a[i];
    int hi = Math.max(x, Math.max(mx * x, mn * x));
    int lo = Math.min(x, Math.min(mx * x, mn * x));
    mx = hi; mn = lo;
    best = Math.max(best, mx);
}
mx = mn = best = a[0]
for x in a[1:]:
    hi = max(x, mx * x, mn * x)
    lo = min(x, mx * x, mn * x)
    mx, mn = hi, lo
    best = max(best, mx)
⏱ Complexity — O(n) time, O(1) space.
Traps to avoid
  • Initialise from a[0], not 0, or all-negative arrays return 0.
  • Max product needs both the running max and min.
  • Circular array: answer = max(kadane, total − minSubarray), except when every element is negative.
Variants and follow-ups
  • Return the subarray itself: remember start whenever you restart.
  • One deletion allowed (LC 1186): two DP states.
When NOT to use

When the subarray need not be contiguous, or you need a count of subarrays rather than the best one.

Hashing: Two Sum, Counting, Grouping

🔥 Frequently asked
When to useAnswer "have I seen X?", "how many times?" or "group items by a key" in O(1) per element.
Detect it"find a pair with this complement" · "first unique" · "group anagrams" · "top K frequent" · counting occurrences · "longest consecutive run".
Intuition

A hash map is a coat-check desk: hand over an item, get an instant answer to "is it here?". Instead of searching the whole array for the partner of x, you ask the desk whether target − x was checked in earlier.

Brute force → optimised

For each element scan the rest for its partner: O(n²). A map that remembers what you have seen makes each lookup O(1): O(n) time for O(n) space.

Core idea

Store what you have seen (value → index, value → count, key → group). For Two Sum look up target − x. For grouping, derive a canonical key (sorted string or a 26-count signature).

How it works
  1. For each x, check whether target − x is already in the map.
  2. If yes, you have the pair; otherwise store x → index.
  3. Store after checking so one element is never used twice.

Two Sum

Map<Integer, Integer> seen = new HashMap<>();
for (int i = 0; i < n; i++) {
    Integer j = seen.get(target - a[i]);
    if (j != null) return new int[]{j, i};
    seen.put(a[i], i);
}
seen = {}
for i, x in enumerate(a):
    if target - x in seen:
        return [seen[target - x], i]
    seen[x] = i

Longest Consecutive Sequence (start only at run beginnings)

Set<Integer> set = new HashSet<>();
for (int x : a) set.add(x);
int best = 0;
for (int x : set) {
    if (set.contains(x - 1)) continue;        // not the start of a run
    int len = 1;
    while (set.contains(x + len)) len++;
    best = Math.max(best, len);
}
s = set(a)
best = 0
for x in s:
    if x - 1 in s:
        continue                          # not the start of a run
    length = 1
    while x + length in s:
        length += 1
    best = max(best, length)
⏱ Complexity — O(n) time, O(n) space.

Dutch National Flag (3-way partition)

🧊 Secondary
When to useThree-way partition of an array in one pass, in place.
Detect it"sort 0s, 1s and 2s" · partition around a pivot into <, =, > · "move all X to the front".
Intuition

Sorting three colours of laundry into three piles using only the floor in front of you: zeros are thrown to the left pile, twos to the right pile, ones are left where they land in the middle. The middle pointer only advances when it is certain what it is standing on.

Brute force → optimised

Core idea

lo = end of the 0-zone, hi = start of the 2-zone, mid scans the unknown middle. Everything before lo is 0, everything after hi is 2.

How it works
  1. mid walks right.
  2. a[mid] == 0: swap with lo, advance both.
  3. a[mid] == 2: swap with hi, hi--, do not advance mid.
  4. a[mid] == 1: advance mid.

Binary Search (basic and on the answer)

🔥 Frequently asked
When to useSorted data, or a numeric answer space where feasibility is monotonic (once true, always true).
Detect itsorted array + O(log n) · "first / last occurrence" · "minimise the maximum" or "maximise the minimum" · "smallest value such that a check passes".
Intuition

Guess-the-number game: each guess eliminates half the possibilities. The deep idea is not about arrays; it is about any yes/no question whose answer flips exactly once along a line: F F F F T T T T. Binary search finds the flip point.

Brute force → optimised

Scan linearly for the first true: O(n). Halving the range each time: O(log n). For "search on answer" it is O(n) per check × O(log range) checks.

Core idea

Keep an invariant such as "the answer is inside [lo, hi]". Look at mid: if the condition holds, the answer is at mid or to its left (hi = mid); otherwise it is to the right (lo = mid + 1).

How it works
  1. Choose lo, hi so the answer is guaranteed inside.
  2. mid = lo + (hi − lo) / 2.
  3. Condition true → hi = mid; false → lo = mid + 1.
  4. Stop when lo == hi; that is the boundary.

Binary Search on a Rotated Array

🧊 Secondary
When to useA sorted array rotated at an unknown pivot.
Detect it"sorted array rotated" · "find the minimum in a rotated array" · plain binary search alone fails.
Intuition

Cut a sorted deck at a random point and swap the halves. Wherever you look at the middle card, at least one side of it is still a perfectly sorted run. Work out which side that is, check whether your target could live in that run, and discard the other half.

Brute force → optimised

Linear scan is O(n). Using the "one half is sorted" fact each step still discards half: O(log n).

Core idea

Compare a[lo] with a[mid] to find the sorted half. If the target lies inside that half's range, search it; otherwise search the other half.

How it works
  1. Compute mid. If a[mid] == target, done.
  2. If a[lo] <= a[mid] the left half is sorted, else the right half is.
  3. If target is within the sorted half's range, go there; otherwise go to the other half.

Quick Select and Merge Sort

🧊 Secondary
When to useKth smallest/largest without a full sort, counting inversions, or a guaranteed O(n log n) stable sort.
Detect it"kth largest/smallest" · "count smaller elements after self" · "count reverse pairs" · "sort with an O(n log n) guarantee".
Intuition

Quick select: to find the 3rd tallest person, split the crowd around one person. If exactly two people are taller, you are done; otherwise only one side can contain your answer, so ignore the other. Merge sort: while merging two sorted halves you see, for free, how many elements jumped past each other: that is the inversion count.

Brute force → optimised

Sorting everything is O(n log n). Quick select discards one side each time: expected n + n/2 + n/4 + … = O(n).

Core idea

Quick select partitions around a pivot and recurses into the single side containing the target index. Merge sort divides, sorts halves, and merges; counting happens during the merge.

How it works
  1. Partition so the pivot lands at its final sorted index p.
  2. p == target → done. p < target → search the right side. p > target → search the left.
  3. kth largest = index n − k in ascending order.

    int pivot = a[hi], i = lo;

        if (a[j] < pivot) { int t = a[i]; a[i] = a[j]; a[j] = t; i++; }

long mergeCount(int[] a, int[] tmp, int lo, int hi) {
    if (hi - lo < 1) return 0;
    int mid = (lo + hi) >>> 1;
    long inv = mergeCount(a, tmp, lo, mid) + mergeCount(a, tmp, mid + 1, hi);
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) {
        if (a[i] <= a[j]) tmp[k++] = a[i++];
        else { tmp[k++] = a[j++]; inv += mid - i + 1; }   // all of a[i..mid] > a[j]
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi) tmp[k++] = a[j++];
    System.arraycopy(tmp, lo, a, lo, hi - lo + 1);
    return inv;
}
def merge_count(a):
    if len(a) <= 1:
        return a, 0
    mid = len(a) // 2
    left, x = merge_count(a[:mid])
    right, y = merge_count(a[mid:])
    out, inv, i, j = [], x + y, 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
            inv += len(left) - i                  # all remaining left > right[j]
    out += left[i:] + right[j:]
    return out, inv

  • Top-K without ordering: quick select, then take the left or right side.

🧊 Secondary
When to useThe problem needs an in-place O(1)-space trick that none of the patterns above cover.
Detect it"majority element" · "missing / duplicate number in 1..n" · "rotate in place" · "add a value to a range many times" · matrix spiral/rotate/zero.
Intuition

These are small, single-purpose tools. Learn the one-sentence idea of each and you can rebuild the code on demand.

Core idea

Boyer–Moore voting cancels pairs of different elements so the majority survives. Cyclic sort puts value x at index x−1. A difference array records range updates as +v at the start and −v just past the end, then a prefix sum reveals the result. Rotation by k is three reversals.

How it works
  1. Voting: keep candidate and count; same → count++, different → count--, at 0 pick a new candidate.
  2. Cyclic sort: while a[i] is in 1..n and not at its home, swap it home; the first index where a[i] != i+1 is the missing number.
  3. Difference array: diff[l] += v, diff[r+1] -= v, prefix-sum at the end.
  4. Rotate by k: reverse all, reverse the first k, reverse the rest.
  5. Matrix: rotate = transpose then reverse each row; zeroes = use the first row and column as markers.

Self-test

Answer in your head first, then click to reveal.

Why does Two Sum II with two pointers never miss the answer?

Each move discards an element that cannot belong to any valid pair with the remaining elements, because the array is sorted. If a[l] + a[r] is too small, a[l] is too small even for the largest remaining partner.

Why must a prefix-sum counter start with {0: 1}?

It represents the empty prefix. Without it, subarrays that start at index 0 (where sum == k already) are never counted.

Why does the variable sliding window run in O(n) even though it has a nested loop?

l and r only ever move forward, so together they make at most 2n moves. Each element is added once and removed once.

Sliding window fails for "subarray sum equals k" with negative numbers. Why?

With negatives, extending the window can decrease the sum and shrinking can increase it, so "shrink while too big" is no longer valid. Use prefix sums with a hash map.

In Dutch flag, why do we not advance mid after swapping with hi?

The element swapped in from hi has not been examined yet; it might be 0, 1 or 2 and must be processed. Elements swapped from lo were already seen.

Binary search: when do you use hi = mid versus hi = mid − 1?

hi = mid when mid itself may be the answer (boundary search with lo < hi). hi = mid − 1 when mid has been ruled out (exact search with lo <= hi).

How do you turn "exactly K" into something a sliding window can do?

Count "at most K" minus "at most K − 1".

When is quick select a bad idea?

When input arrives as a stream, when a stable order is needed, or when a deterministic worst case matters (use a heap or median-of-medians).

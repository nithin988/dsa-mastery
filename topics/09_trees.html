Binary Trees and BSTs — Pattern Guide

Trees are recursion made visible. This guide covers thinking recursively on trees, depth-first traversals and path problems, level-order BFS, the "record one value, return another" path pattern, binary search trees, lowest common ancestors, constructing and serialising trees, tree dynamic programming and iterative traversals. Each pattern has the intuition, a step-through animation that draws the tree, Java and Python code, and a ladder of LeetCode problems.

How to use this page

For each section: read Detect and Intuition, play the animation, then try to write the skeleton from memory before opening the code. Finish by solving the problem ladder in order.

The mindset

Every tree problem is the same three questions: what do I do at the null case, what do I need from my two children, and what do I return to my parent? Decide whether the answer flows down (pass state as arguments), up (return values) or across levels (BFS), and remember that a BST gives you an extra gift: inorder is sorted.

Ask these questions on every tree problem:

  • What is the answer for an empty tree? → the base case.
  • What do I need from the left and right subtrees? → the return value.
  • Is information passed down (bounds, sum so far) or up (height, gain)?
  • Do I need levels or shortest depth? → BFS with a queue.
  • Is it a BST? → use ordering (inorder, bounds, go left/right).

Thinking recursively on trees (height, depth, symmetry)

🔥 Frequently asked
When to useA property of a tree can be written in terms of the same property of its left and right subtrees.
Detect it"maximum depth" · "same tree" · "invert" · "symmetric" · "balanced" · "diameter" · "subtree of another tree".
Intuition

A tree is a node plus two smaller trees. So to answer a question about the whole tree, ask the same question of the left subtree and the right subtree (the recursion will handle them), then combine the two answers with this node's own value. The base case is the empty tree.

Brute force → optimised

Walking the tree repeatedly for each node (for example recomputing height at every node to check balance) gives O(n²). One recursion that returns the information the parent needs (height, plus a flag) gives O(n).

Core idea

f(node): if node == null return the base value; l = f(left), r = f(right); return combine(node, l, r). Often a global best is updated on the way while the function returns something else upward (diameter).

How it works
  1. Base case: null → 0 / true / empty result.
  2. Recurse into both children.
  3. Combine with the node: 1 + max(l, r), l && r && node.val == …, …
  4. If the answer is a global max (diameter), update it from l and r before returning.

height and diameter

int maxDepth(TreeNode r) { return r == null ? 0 : 1 + Math.max(maxDepth(r.left), maxDepth(r.right)); }

int best = 0;
int height(TreeNode n) {                       // diameter = longest path in edges
    if (n == null) return 0;
    int l = height(n.left), r = height(n.right);
    best = Math.max(best, l + r);              // path through this node
    return 1 + Math.max(l, r);                 // only one side can go up
}
def max_depth(r):
    return 0 if not r else 1 + max(max_depth(r.left), max_depth(r.right))

best = 0
def height(n):                                 # diameter = longest path in edges
    global best
    if not n:
        return 0
    l, r = height(n.left), height(n.right)
    best = max(best, l + r)                    # path through this node
    return 1 + max(l, r)                       # only one side can go up

invert, same tree and symmetric

TreeNode invert(TreeNode r) {
    if (r == null) return null;
    TreeNode l = invert(r.left), rt = invert(r.right);
    r.left = rt; r.right = l;
    return r;
}
boolean same(TreeNode a, TreeNode b) {
    if (a == null || b == null) return a == b;
    return a.val == b.val && same(a.left, b.left) && same(a.right, b.right);
}
boolean mirror(TreeNode a, TreeNode b) {                 // symmetric: compare left with the mirror of right
    if (a == null || b == null) return a == b;
    return a.val == b.val && mirror(a.left, b.right) && mirror(a.right, b.left);
}
def invert(r):
    if not r:
        return None
    r.left, r.right = invert(r.right), invert(r.left)
    return r

def same(a, b):
    if not a or not b:
        return a is b
    return a.val == b.val and same(a.left, b.left) and same(a.right, b.right)

def mirror(a, b):                                        # symmetric: compare left with the mirror of right
    if not a or not b:
        return a is b
    return a.val == b.val and mirror(a.left, b.right) and mirror(a.right, b.left)
⏱ Complexity — O(n) time, O(h) stack space (h = height: log n balanced, n for a chain).
Traps to avoid
  • Forgetting the null base case; or checking a == b only after dereferencing.
  • Diameter counts edges (l + r) vs nodes (l + r + 1); read the problem.
  • Balanced-check: do not recompute heights at every node; return −1 from the recursion as a failure flag.
  • Deep (skewed) trees overflow the stack at ~10⁴ depth in Java/Python: use an explicit stack.
Variants and follow-ups
  • Subtree of another tree: for each node run same, or serialise both and search.
  • Minimum depth: a node with one child is not a leaf.
  • Count nodes in a complete tree in O(log² n) using heights.
When NOT to use

When the property depends on global order (use traversal) or on values elsewhere in the tree (use the path-carrying patterns).

DFS traversals and root-to-leaf paths

🔥 Frequently asked
When to useYou need every node in a specific order, or you accumulate state while walking down root-to-leaf paths.
Detect it"inorder / preorder / postorder" · "path sum" · "all root-to-leaf paths" · "sum root to leaf numbers" · "number of paths with sum".
Intuition

Walk around the outline of the tree with your hand on the wall. You pass each node three times: on the way down its left side (preorder moment), underneath it between the subtrees (inorder), and on the way up its right side (postorder). Choose the moment at which you write the node's value down.

Brute force → optimised

Collecting paths by repeatedly searching from the root is wasteful. A single DFS carrying the running state (current sum, current path) as arguments visits each node once.

Core idea

dfs(node, state): do the work before recursing (preorder), between (inorder) or after (postorder). Pass the accumulated state down as parameters; backtrack mutable state (a path list) after the calls.

How it works
  1. Base case: null returns.
  2. Preorder work: use node (push to path, add to sum).
  3. Recurse left, (inorder work), recurse right.
  4. Postorder work, then undo any mutable state (pop the path).

boolean hasPathSum(TreeNode n, int target) {
    if (n == null) return false;
    if (n.left == null && n.right == null) return n.val == target;    // leaf: nothing left to add
    return hasPathSum(n.left, target - n.val) || hasPathSum(n.right, target - n.val);
}
def pre(n, out):
    if not n: return
    out.append(n.val); pre(n.left, out); pre(n.right, out)

def inorder(n, out):
    if not n: return
    inorder(n.left, out); out.append(n.val); inorder(n.right, out)

def post(n, out):
    if not n: return
    post(n.left, out); post(n.right, out); out.append(n.val)

def has_path_sum(n, target):
    if not n:
        return False

    return has_path_sum(n.left, target - n.val) or has_path_sum(n.right, target - n.val)

When you need nodes level by level (BFS) or the structure of subtrees combined bottom-up (return values).

BFS: level order and its variations

🔥 Frequently asked
When to useYou need nodes grouped by depth, the nearest leaf, or a view of the tree from the side.
Detect it"level order" · "zigzag" · "right side view" · "minimum depth" · "average of levels" · "maximum width".
Intuition

Ripples in a pond: everything at distance 1 from the root is dealt with before anything at distance 2. A queue naturally gives that order: new children join the back while the current level is still being served from the front. If you freeze the queue's size at the start of a round, that round is exactly one level.

Brute force → optimised

DFS with a depth parameter and a list-of-lists also gives levels, but BFS finds the shallowest answer first, so you can stop early (minimum depth).

Core idea

queue = [root]; while not empty: size = queue.size(); repeat size times: pop node, record it, enqueue its non-null children.

How it works
  1. Start with the root in the queue.
  2. For each round take size = queue.size().
  3. Pop size nodes; append their values to the level list; push children.
  4. Add the level list to the result.

level order, right-side view and zigzag

List<List<Integer>> res = new ArrayList<>();
if (root == null) return res;
Queue<TreeNode> q = new ArrayDeque<>();
q.add(root);
boolean leftToRight = true;
while (!q.isEmpty()) {
    int size = q.size();                                   // exactly this level
    LinkedList<Integer> level = new LinkedList<>();
    for (int i = 0; i < size; i++) {
        TreeNode n = q.poll();
        if (leftToRight) level.addLast(n.val); else level.addFirst(n.val);   // zigzag
        if (n.left != null) q.add(n.left);
        if (n.right != null) q.add(n.right);
    }
    res.add(level);                                        // right view: level.getLast() before reversing
    leftToRight = !leftToRight;
}

    return res

minimum depth (stop at the first leaf)

if (root == null) return 0;
Queue<TreeNode> q = new ArrayDeque<>(); q.add(root);
int depth = 1;
while (!q.isEmpty()) {
    for (int i = q.size(); i > 0; i--) {
        TreeNode n = q.poll();
        if (n.left == null && n.right == null) return depth;     // nearest leaf
        if (n.left != null) q.add(n.left);
        if (n.right != null) q.add(n.right);
    }
    depth++;
}
return depth;
if not root:
    return 0
q, depth = deque([root]), 1
while q:
    for _ in range(len(q)):
        n = q.popleft()
        if not n.left and not n.right:
            return depth                                         # nearest leaf
        if n.left: q.append(n.left)
        if n.right: q.append(n.right)
    depth += 1
⏱ Complexity — O(n) time, O(w) space where w is the maximum width (up to n/2).
Traps to avoid
  • Capture size = q.size() before the inner loop (the queue grows inside it).
  • Do not enqueue null children.
  • Minimum depth: a node with one child is not a leaf; the BFS version handles this automatically.
  • Maximum width: number nodes with heap indexes (2i, 2i + 1) and use long / relative indexes to avoid overflow.
Variants and follow-ups
  • Right-side view: last node of each level (or DFS visiting right first).
  • Average / maximum of each level: aggregate inside the loop.
  • Bottom-up level order: reverse the result list.
When NOT to use

When you need the path itself or bottom-up information (use DFS).

Path problems: return one value, record another

🔥 Frequently asked
When to useThe answer is a best path that can bend at any node (maximum path sum, longest same-value path).
Detect it"maximum path sum" · "longest univalue path" · "diameter" · "path may start and end anywhere" · "distribute coins".
Intuition

A path that bends at a node uses both of its sides (left arm + node + right arm). But when this node reports to its parent, the parent can only extend one arm of it. So each node does two different things: it records the best bent path through itself into a global answer, and it returns the best single arm (node + the better child arm). Negative arms are dropped by clamping at 0.

Brute force → optimised

Trying every pair of nodes as path endpoints is O(n²). A single post-order pass with this record-versus-return split is O(n).

Core idea

gain(node) = node.val + max(0, gain(left), gain(right)) is what you return. Before returning, set best = max(best, node.val + max(0, gain(left)) + max(0, gain(right))).

How it works
  1. Post-order: compute l = max(0, gain(left)), r = max(0, gain(right)).
  2. Record best = max(best, node.val + l + r).
  3. Return node.val + max(l, r) to the parent.
  4. Initialise best = −∞ (not 0) so all-negative trees work.

int best = Integer.MIN_VALUE;
int gain(TreeNode n) {

int good(TreeNode n, int maxSoFar) {
    if (n == null) return 0;

        return 0

Traps to avoid
  • Returning the bent path (both arms) to the parent: wrong, the parent can only use one arm.
  • Initialising best to 0 breaks trees whose nodes are all negative.
  • For diameter-style problems edge count vs node count differs by one.
  • Longest univalue path: only extend an arm if the child has the same value as the node.
Variants and follow-ups
  • Longest univalue path: arms extend only through equal values.
  • Distribute coins: each subtree returns its surplus; moves += |surplus|.
  • Binary tree cameras: tri-state return (covered, camera, needs cover) (pattern 8).
When NOT to use

Paths that must go from the root downward (a simple DFS with accumulated state is enough).

Binary search trees: search, insert, delete, validate

🔥 Frequently asked
When to useThe tree has the BST invariant and you want O(h) lookup, or you need sorted order.
Detect it"search in a BST" · "insert / delete" · "validate BST" · "kth smallest" · "two sum IV" · "minimum absolute difference" · "recover a BST".
Intuition

A BST is binary search turned into a shape: at each node one comparison throws away half of the remaining values. The ordering also means an inorder walk lists values in sorted order, so many BST tasks (kth smallest, minimum difference, validation, recovery) are really "walk inorder and compare neighbours".

Brute force → optimised

Treating a BST as a plain tree (full DFS) costs O(n) per query. Using the ordering gives O(h): O(log n) when balanced.

Core idea

Search/insert: compare, go left or right. Delete: leaf → remove; one child → replace by the child; two children → copy the inorder successor (smallest in the right subtree) and delete it. Validate: carry an allowed (low, high) range down, or check that inorder is strictly increasing.

How it works
  1. Search: val < node → left, val > node → right, else found.
  2. Insert: walk down to a null child and attach.
  3. Delete: handle 0, 1, 2 children (successor swap for two).
  4. Validate: pass (low, high) bounds; each node must satisfy low < val < high.

TreeNode delete(TreeNode root, int key) {
    if (root == null) return null;
    if (key < root.val) root.left = delete(root.left, key);
    else if (key > root.val) root.right = delete(root.right, key);
    else {

Lowest common ancestor and tree distances

🔥 Frequently asked
When to useFind where two nodes' root paths meet, or measure distances between nodes.
Detect it"lowest common ancestor" · "all nodes at distance K" · "smallest subtree with all deepest nodes" · "distance between two nodes".
Intuition

Imagine two climbers at nodes p and q moving up toward the root. The lowest common ancestor is the first node they both pass. In a recursion from the top: a node reports "I found a target in my subtree" upward; the first node that hears reports from both sides (or is itself a target and hears from one side) is the meeting point.

Brute force → optimised

Store the root path to each node and compare them: O(n) time and extra memory. The recursive return-value solution does it in one pass with no paths.

Core idea

lca(node): if node is null or equals p or q, return it. Recurse into both children. If both return non-null, node is the LCA; otherwise return whichever is non-null. For a BST, compare values and walk down: if both are smaller go left, both larger go right, else the current node is the LCA.

How it works
  1. Base: null, p, or q → return the node.
  2. l = lca(left), r = lca(right).
  3. Both non-null → return node.
  4. Otherwise return the non-null one (or null).

TreeNode lca(TreeNode r, TreeNode p, TreeNode q) {
    if (r == null || r == p || r == q) return r;
    TreeNode l = lca(r.left, p, q), rt = lca(r.right, p, q);

TreeNode lcaBST(TreeNode r, TreeNode p, TreeNode q) {

        if (p.val < r.val && q.val < r.val) r = r.left;
        else if (p.val > r.val && q.val > r.val) r = r.right;
        else return r;                                      // they split here (or one equals r)

def lca(r, p, q):
    if not r or r is p or r is q:
        return r
    l, rt = lca(r.left, p, q), lca(r.right, p, q)
    if l and rt:
        return r                                            # p and q are on different sides
    return l or rt

def lca_bst(r, p, q):
    while r:
        if p.val < r.val and q.val < r.val:
            r = r.left
        elif p.val > r.val and q.val > r.val:
            r = r.right
        else:
            return r                                        # they split here (or one equals r)
    return None
⏱ Complexity — Binary tree: O(n) time, O(h) space. BST: O(h) time, O(1) space.
Traps to avoid
  • The recursion assumes both p and q exist in the tree; if not, you need a second pass or counters.
  • A node can be its own ancestor: if p is above q the answer is p.
  • Compare node references, not values, unless values are unique and the problem says so.
  • Distance K nodes: convert to a graph (parent pointers) and BFS from the target.
Variants and follow-ups
  • LCA of deepest leaves: return (depth, node) from each subtree.
  • Distance between p and q: depth(p) + depth(q) − 2·depth(lca).
  • All nodes at distance K: parent map + BFS.
When NOT to use

Many repeated LCA queries on a fixed tree: preprocess with binary lifting or Euler tour + RMQ.

Construct and serialise trees

🧊 Secondary
When to useRebuild a tree from traversals, convert a sorted array to a balanced BST, or turn a tree into a string and back.
Detect it"construct from preorder and inorder" · "serialize and deserialize" · "sorted array to BST" · "flatten" · "maximum binary tree".
Intuition

Preorder always starts with the root; inorder tells you how many nodes lie to the left of that root. So the first preorder value is a root, finding it in inorder splits the remaining values into a left group and a right group, and the same trick rebuilds each subtree. Serialisation is just recording a preorder with explicit null markers so the shape is unambiguous.

Brute force → optimised

Searching inorder for each root costs O(n) each, so O(n²) total. A hash map from value to inorder index makes each lookup O(1), O(n) overall.

Core idea

build(l, r) over the inorder window: take pre[idx++] as the root, m = pos[root]; root.left = build(l, m − 1); root.right = build(m + 1, r). Always build left before right so the preorder pointer advances correctly.

How it works
  1. Map each inorder value to its index.
  2. Keep a global preorder pointer.
  3. Take the next preorder value as the root; find m in inorder.
  4. Build the left window [l, m − 1], then the right window [m + 1, r].

TreeNode build(int[] preorder, int l, int r) {
    if (l > r) return null;
    int rootVal = preorder[pre++];                          // next unused preorder value is the root
    TreeNode node = new TreeNode(rootVal);
    int m = pos.get(rootVal);                               // pos: value -> index in inorder
    node.left = build(preorder, l, m - 1);                  // left first: preorder visits it first
    node.right = build(preorder, m + 1, r);
    return node;
}
def build_tree(preorder, inorder):
    pos = {v: i for i, v in enumerate(inorder)}
    it = iter(preorder)
    def build(l, r):
        if l > r:
            return None
        root = TreeNode(next(it))                           # next unused preorder value is the root
        m = pos[root.val]
        root.left = build(l, m - 1)                         # left first: preorder visits it first
        root.right = build(m + 1, r)
        return root

Tree DP: return a tuple from each node

🧊 Secondary
When to useYou decide something per node (rob it, put a camera on it) and the choices of neighbours interact.
Detect it"house robber III" · "binary tree cameras" · "maximum sum BST" · "split the tree to maximise a product" · "largest BST subtree".
Intuition

At each node you face a small decision, and the only thing that matters about each child subtree is the best result for each state of the child. So each node returns a tiny table, for example [best if I skip this node, best if I take this node], and the parent combines the tables of its children. It is dynamic programming where the "order" is the tree itself.

Brute force → optimised

Trying every subset of nodes is exponential. Plain recursion that recomputes sub-results is O(2ⁿ) without memoisation. Returning the tuple computes each subtree once: O(n).

Core idea

Define the states, then write the transition: take = val + skip(left) + skip(right); skip = max(left) + max(right). Return (skip, take) and answer with max at the root.

How it works
  1. List the states a node can be in (skip, take / covered, camera, needs cover).
  2. Write the value for each state using the children's tuples.
  3. Return the tuple from a post-order recursion.
  4. The answer is the best of the root's states.

Iterative traversals and O(1)-space walks

🧊 Secondary
When to useRecursion depth could be huge, you must produce nodes lazily (an iterator), or you need O(1) extra space.
Detect it"BST iterator" · "inorder without recursion" · "iterative postorder" · "O(1) space traversal" · "flatten in place".
Intuition

Recursion secretly keeps a stack of "nodes whose left subtree I am still exploring". Do the same by hand: dive left, pushing every node you pass. When you cannot go further left, pop the top (that node is next in inorder), visit it, and step into its right subtree. Morris traversal goes further: it temporarily threads a link from each node's inorder predecessor back to the node, so no stack is needed.

Brute force → optimised

Recursive traversal uses O(h) call-stack space and can overflow on skewed trees. The explicit stack has the same O(h) space but no overflow risk; Morris uses O(1) extra space.

Core idea

Inorder: while cur != null or stack: while cur: push, cur = left; pop → visit; cur = node.right. BST iterator: keep the same stack lazily; next() pops and pushes the left chain of the right child.

How it works
  1. Dive left, pushing nodes.
  2. Pop a node and visit it.
  3. Move to its right child and repeat.
  4. Preorder: push right then left; postorder: reverse a modified preorder, or use two stacks.

TreeNode cur = root;
while (cur != null) {
    if (cur.left == null) { visit(cur); cur = cur.right; }
    else {
        TreeNode pre = cur.left;
        while (pre.right != null && pre.right != cur) pre = pre.right;   // inorder predecessor
        if (pre.right == null) { pre.right = cur; cur = cur.left; }       // thread back to cur
        else { pre.right = null; visit(cur); cur = cur.right; }          // remove the thread
    }
}
cur = root

    if not cur.left:
        visit(cur)
        cur = cur.right
    else:
        pre = cur.left
        while pre.right and pre.right is not cur:
            pre = pre.right                                              # inorder predecessor
        if not pre.right:
            pre.right = cur                                              # thread back to cur
            cur = cur.left
        else:
            pre.right = None                                             # remove the thread
            visit(cur)
            cur = cur.right

Traps to avoid
  • The inner while (cur != null) is required; a single if skips deep left chains.
  • Iterator next() must push the left chain of the right child after popping.

  • Iterative postorder is trickiest: reverse of (node, right, left), or track the last visited node.
Variants and follow-ups
  • Iterative preorder: stack; push right child first so left is processed first.
  • Leaf-similar trees: compare the leaf sequences produced lazily by two iterators.
  • Convert BST to greater tree: reverse inorder (right, node, left) with a running sum.
When NOT to use

When recursion depth is small and clarity matters more (plain recursion is fine).

Rule of thumb

if the answer for a node depends on its children, recurse and return; if it depends on its ancestors, pass it down; if it is about levels, use a queue; if the tree is a BST, use its order.

Self-test

Answer in your head first, then click to reveal.

Why is the time complexity of most tree recursions O(n) and the space O(h)?

Each node is visited once, and the recursion stack holds one frame per level of the current path, so its depth is the height of the tree.

In maximum path sum, why do we return node + max(l, r) but record node + l + r?

A path that bends at the node uses both arms, but the parent can extend only one arm of this node, so only one arm can be returned.

How do you validate a BST correctly?

Carry (low, high) bounds down so every node is compared with all its ancestors, or check that an inorder traversal is strictly increasing.

Why does inorder traversal of a BST give sorted order?

Left subtree values are smaller than the node and right subtree values are larger, so visiting left, node, right always lists values in ascending order.

In the LCA recursion, when is a node the answer?

When both subtree calls return non-null (one target on each side), or when the node itself is a target and the other target is below it.

Which two traversals determine a binary tree uniquely?

Inorder together with preorder, or inorder together with postorder (for unique values). Preorder and postorder alone are ambiguous in general.

Why must size = q.size() be read before the inner loop in level-order traversal?

The queue grows while you add children, so the size must be fixed at the start of the round to know where the level ends.

What is the idea of the tree-DP pair (skip, take)?

Each subtree reports its best result for each state of its root, and the parent combines the children's reports according to which states are compatible.

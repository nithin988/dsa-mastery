Heaps and Priority Queues — Pattern Guide

A heap answers "what is the smallest (or largest) thing right now?" in O(1) and keeps that answer up to date in O(log n). This guide covers heap mechanics, top-K, the two-heap median, k-way merge, greedy with heaps, lazy deletion, heap sort and comparators, Dijkstra, and frequency heaps. Each pattern has the intuition, a step-through animation that draws the heap as a tree, Java and Python code, and a ladder of LeetCode problems.

The mindset

Reach for a heap when the problem keeps asking for the best remaining item while the set of items changes. Three questions pick the pattern: do I need the k best (size-k heap), the middle (two heaps), or the next in global order across several sources (k-way merge, Dijkstra)? And remember that a heap is only partially ordered: only the top is guaranteed.

Ask these questions on every heap problem:

  • Do I repeatedly need the min or max of a changing set? → heap.
  • Do I need only the k best? → a heap of size k, of the opposite type.
  • Do I need the median or a boundary between two halves? → two heaps.
  • Am I merging sorted sources or expanding the cheapest state next? → k-way merge / Dijkstra.
  • Do entries expire or change? → lazy deletion.

Heap fundamentals: sift up, sift down, heapify

🔥 Frequently asked
When to useYou repeatedly need the smallest (or largest) item of a changing collection.
Detect it"always take the largest / smallest" · "kth largest in a stream" · "last stone weight" · "priority" · "process in order of cost".
Intuition

A tournament bracket where the champion is always at the top: when a new player joins they play their way up while they beat their parent; when the champion leaves, the last player is moved to the top and plays their way down until they are no better than both children. Both walks are at most the height of the tree (log n), and the champion is available instantly.

Brute force → optimised

Keeping the collection sorted costs O(n) per insert; scanning for the minimum costs O(n) per query. A heap gives O(log n) insert and remove, and O(1) peek.

Core idea

A complete binary tree stored in an array: parent of i is (i − 1) / 2, children are 2i + 1 and 2i + 2. Min-heap rule: parent ≤ children. Push = append, then sift up. Pop = move the last element to the root, then sift down. Heapify an array in O(n) by sifting down from the last parent to the root.

How it works
  1. Push x: append at index n, swap with the parent while smaller.
  2. Peek: return a[0].
  3. Pop: save a[0], put the last element at the root, sift down choosing the smaller child each time.
  4. Heapify: for i = n/2 − 1 down to 0, sift down.

Skeleton

min-heap implemented by hand

class MinHeap {
    int[] a = new int[16]; int n = 0;
    void push(int x) {
        if (n == a.length) a = Arrays.copyOf(a, 2 * n);
        a[n] = x; int i = n++;
        while (i > 0 && a[(i - 1) / 2] > a[i]) { swap(i, (i - 1) / 2); i = (i - 1) / 2; }   // sift up
    }
    int pop() {
        int top = a[0]; a[0] = a[--n]; int i = 0;
        while (true) {                                                                       // sift down
            int l = 2 * i + 1, r = l + 1, m = i;
            if (l < n && a[l] < a[m]) m = l;
            if (r < n && a[r] < a[m]) m = r;
            if (m == i) break;
            swap(i, m); i = m;
        }
        return top;
    }
    void swap(int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
}
class MinHeap:
    def __init__(self):
        self.a = []
    def push(self, x):
        a = self.a
        a.append(x); i = len(a) - 1
        while i > 0 and a[(i - 1) // 2] > a[i]:                  # sift up
            a[(i - 1) // 2], a[i] = a[i], a[(i - 1) // 2]
            i = (i - 1) // 2
    def pop(self):
        a = self.a
        top, a[0] = a[0], a[-1]
        a.pop(); i, n = 0, len(a)
        while True:                                              # sift down
            l, r, m = 2 * i + 1, 2 * i + 2, i
            if l < n and a[l] < a[m]: m = l
            if r < n and a[r] < a[m]: m = r
            if m == i: break
            a[i], a[m] = a[m], a[i]; i = m
        return top
⏱ Complexity — Push / pop O(log n), peek O(1), heapify O(n), space O(n). Removing an arbitrary item is O(n) to find it.
Traps to avoid
  • A heap is not sorted; only the root is guaranteed to be the minimum. Iterating a PriorityQueue does not give sorted order.
  • Python's heapq is a min-heap only: negate values for a max-heap.
  • Java PriorityQueue.remove(obj) is O(n); use lazy deletion for frequent removals.
  • Do not mutate an element that is inside the heap; remove and re-insert instead.
Variants and follow-ups
  • Max-heap: reverse the comparison.
  • Indexed / decrease-key heaps for Dijkstra optimisations.
  • d-ary heaps and Fibonacci heaps exist, but binary heaps are what interviews expect.
When NOT to use

When you need sorted iteration or range queries (use a balanced tree / TreeMap), or only one-time min / max (a single pass suffices).

Top K: keep a heap of size k

🔥 Frequently asked
When to useYou need the k largest, k smallest, k most frequent or k closest items.
Detect it"kth largest" · "top k frequent" · "k closest points" · "k closest elements" · "k smallest pairs".
Intuition

You are selecting a team of k tallest people from a crowd walking past one at a time. Keep the current best k in a little room; the shortest of the k stands at the door (min-heap root). A new person who is not taller than the door person can never make the team. If they are taller, they swap places with the door person. The door person is exactly the kth tallest so far.

Brute force → optimised

Sorting everything is O(n log n). A heap of size k costs O(log k) per element: O(n log k) time and O(k) space, and it works on a stream you cannot store.

Core idea

For k largest keep a min-heap of size k (pop the smallest when it grows past k). For k smallest keep a max-heap of size k. The root is the boundary element (kth largest / kth smallest).

How it works
  1. Create an empty heap of the opposite type.
  2. For each item: push it.
  3. If the heap size exceeds k, pop the root.
  4. At the end the heap holds the answer; the root is the kth.

Traps to avoid
  • The heap type is the opposite of what you want: k largest ↔ min-heap.
  • Compare squared distances; avoid sqrt and floating-point error.
  • Pop after pushing (size k + 1 → k) or compare with the root before pushing; both work.
  • When k is close to n, sorting or quickselect (O(n) average) may be simpler.
Variants and follow-ups
  • Quickselect gives the kth in O(n) average but needs the whole array in memory.
  • k closest elements to x in a sorted array: binary search on the left bound.
  • Top k frequent words: tie-break alphabetically in the comparator.
When NOT to use

k = 1 (a single pass min / max), or k ≈ n (just sort).

Two heaps: running median

🔥 Frequently asked
When to useYou need the median (or any middle value) of a growing or sliding collection.
Detect it"median from a data stream" · "sliding window median" · "maximise capital (IPO)" · "balance two halves".
Intuition

Split the numbers into the smaller half and the larger half. The median is at the boundary, so you only need the biggest of the small half and the smallest of the large half: exactly what a max-heap and a min-heap hand you instantly. Keep the halves the same size (or the lower one bigger by one) and the median is one or two heap tops.

Brute force → optimised

Sorting after each insert is O(n log n) per query; inserting into a sorted array is O(n). Two heaps make insert O(log n) and median O(1).

Core idea

low = max-heap of the smaller half, high = min-heap of the larger half. Add: push to low, move low's top to high, and if high is bigger move its top back. Median: low.top if the sizes differ, else the average of the two tops.

How it works
  1. low.add(x).
  2. high.add(low.poll()) (keeps every low ≤ every high).
  3. If high.size() > low.size(), low.add(high.poll()).
  4. Median = low.peek() if low is larger, else (low.peek() + high.peek()) / 2.

Skeleton

find median from a data stream

class MedianFinder {
    PriorityQueue<Integer> low = new PriorityQueue<>(Collections.reverseOrder());   // max-heap: smaller half
    PriorityQueue<Integer> high = new PriorityQueue<>();                             // min-heap: larger half
    void addNum(int x) {
        low.offer(x);
        high.offer(low.poll());                       // largest of the small half moves up
        if (high.size() > low.size()) low.offer(high.poll());   // rebalance: low may be one bigger
    }
    double findMedian() {
        return low.size() > high.size() ? low.peek() : (low.peek() + high.peek()) / 2.0;
    }
}
import heapq
class MedianFinder:
    def __init__(self):
        self.low, self.high = [], []                  # low is a max-heap (negated), high a min-heap
    def addNum(self, x):
        heapq.heappush(self.low, -x)
        heapq.heappush(self.high, -heapq.heappop(self.low))   # largest of the small half moves up
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))
    def findMedian(self):
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2
⏱ Complexity — add O(log n), median O(1), space O(n).
Traps to avoid
  • Use / 2.0 (or / 2 in Python 3) for the average; integer division loses the half.
  • Keep the invariant |low| − |high| ∈ {0, 1} after every insert.
  • Python: negate values in the max-heap, and negate again when reading.
  • Sliding window median needs deletions: use lazy deletion with counters or a sorted multiset.
Variants and follow-ups
  • Sliding window median: two heaps with lazy deletion, or one balanced structure.
  • IPO / maximise capital: a min-heap of projects by capital plus a max-heap of affordable profits.
  • Median of two sorted arrays: binary search instead (topic 02).
When NOT to use

A static array (use quickselect) or when only approximate quantiles are needed (use sketches).

K-way merge

🔥 Frequently asked
When to useYou have k sorted sequences (or a sorted matrix / pair space) and need the smallest items in order.
Detect it"merge k sorted lists" · "kth smallest in a sorted matrix" · "k pairs with smallest sums" · "smallest range covering k lists" · "ugly numbers".
Intuition

k queues of customers, each already in order of arrival time. The next customer to serve overall is the earliest among the fronts of the k queues. A heap holds exactly those k fronts: pop the earliest, serve them, and put their queue's next customer in. The heap never grows beyond k.

Brute force → optimised

Concatenate everything and sort: O(N log N). Comparing the k heads linearly each time: O(N·k). The heap gives O(N log k).

Core idea

Heap entries (value, listIndex, positionInList). Pop the smallest, output it, and push the next element of that same list (if any). For implicit sorted spaces (matrix rows, pair sums a[i] + b[j]) the "next" is the neighbour to the right or below.

How it works
  1. Push the first element of every list.
  2. Pop the minimum and append it to the output.
  3. Push the next element from the same list.
  4. Repeat until the heap is empty (or you have produced k items).

Traps to avoid
  • Python tuples compare element by element: add an index tiebreaker so non-comparable objects are never compared.
  • Push the next element of the list you just popped, not of an arbitrary list.
  • Smallest range covering k lists: also track the current maximum while popping minima.
  • Sorted matrix: start with the first column (or row), not all cells.
Variants and follow-ups
  • Kth smallest in a sorted matrix: pop k times (or binary search on value).
  • Ugly Number II / super ugly numbers: k pointers = k implicit sorted lists.
  • Merge k sorted arrays into one array: same heap with array indexes.
When NOT to use

k = 2 (a simple two-pointer merge is enough) or when all data fits and you can just sort.

Greedy with a heap: always take the best available

🔥 Frequently asked
When to useAt each step the greedy choice is "the smallest cost / largest gain currently available", and the available set changes.
Detect it"minimum cost to connect" · "furthest building you can reach" · "task scheduler" · "minimum refuelling stops" · "hire k workers" · "meeting rooms".
Intuition

Connecting ropes: every time you join two ropes, the result gets joined again later and its cost is paid again. So the shortest ropes should be joined first, when they are still cheap, and the long ones last. The heap hands you the two shortest in O(log n) every time. The same "best option right now" idea solves scheduling: always run the task with the most remaining work, or spend the cheapest resource first.

Brute force → optimised

Re-sorting after each step is O(n log n) per step, O(n² log n) overall. A heap makes each step O(log n).

Core idea

State the greedy rule, then maintain the candidate set in a heap: pop the best, act, push any new candidates. A regret variant: take every option now, and when you run out of a resource, undo (pop) the most wasteful earlier choice.

How it works
  1. Identify what you repeatedly need: the cheapest, the largest, the earliest.
  2. Heap the candidates by that key.
  3. Loop: pop the best, update the answer, push new candidates created by the action.
  4. For regret problems: push every choice, and pop the worst one when a limit is exceeded.

Lazy deletion and heap + hash map designs

🧊 Secondary
When to useElements expire or change (leave a window, price updated, order cancelled) but you still need the current best.
Detect it"sliding window maximum with a heap" · "stock price fluctuation" · "order backlog" · "number container system" · "design Twitter feed".
Intuition

Instead of searching the pile to throw out an old paper, just leave it there and check the top paper each time you need the best one: if it is out of date, throw it away and look at the next. Stale items never affect the answer because you only ever act on the top, and each item is thrown away at most once.

Brute force → optimised

Removing an arbitrary item from a heap is O(n) (find, then re-heapify). Lazy deletion keeps every operation O(log n) amortised.

Core idea

Store enough in each entry to tell whether it is still valid (an index, a timestamp, a version). Keep a source-of-truth structure (a map, the current window bounds). Before using the top: while top is stale: pop.

How it works
  1. Push entries with an identity (value, index / timestamp).
  2. Update the truth: window start, map[key] = newValue.
  3. Before reading the top, pop while the top does not match the truth.
  4. Each entry is pushed once and popped once: O(log n) amortised.

Heap sort and comparator-driven heaps

🧊 Secondary
When to useYou need an O(1)-space O(n log n) sort, or the priority is a custom rule (length then alphabet, distance then index).
Detect it"sort in place with guaranteed O(n log n)" · "kth largest number as strings" · "distant barcodes" · priorities with several keys.
Intuition

Heap sort keeps the unsorted part as a heap and builds the sorted part from the back: the maximum is at the root, swap it to the last slot (its final place), shrink the heap, and sift the new root down to restore order. After n rounds the array is sorted. For custom priorities, the comparator is the rule that says which of two items is "smaller" (comes out first).

Brute force → optimised

Selection sort finds the maximum in O(n) every round: O(n²). The heap finds it in O(1) and repairs in O(log n).

Core idea

(1) Heapify the array into a max-heap (sift down from n/2 − 1 to 0). (2) For end = n − 1 down to 1: swap a[0] and a[end], then sift down the root within [0, end).

How it works
  1. Heapify: sift down each parent from the last one to the root.
  2. Swap the root (max) with the last element of the heap.
  3. Shrink the heap by one; sift the new root down.
  4. Repeat until the heap has one element.

heap sort in place

void heapSort(int[] a) {
    int n = a.length;
    for (int i = n / 2 - 1; i >= 0; i--) sift(a, i, n);          // build a max-heap in O(n)
    for (int end = n - 1; end > 0; end--) {
        int t = a[0]; a[0] = a[end]; a[end] = t;                  // max goes to its final place
        sift(a, 0, end);                                          // repair the shrunken heap
    }
}
void sift(int[] a, int i, int n) {
    while (true) {
        int l = 2 * i + 1, r = l + 1, m = i;
        if (l < n && a[l] > a[m]) m = l;
        if (r < n && a[r] > a[m]) m = r;
        if (m == i) return;
        int t = a[i]; a[i] = a[m]; a[m] = t; i = m;
    }
}
def heap_sort(a):
    n = len(a)
    def sift(i, size):
        while True:
            l, r, m = 2 * i + 1, 2 * i + 2, i
            if l < size and a[l] > a[m]: m = l
            if r < size and a[r] > a[m]: m = r
            if m == i: return
            a[i], a[m] = a[m], a[i]
            i = m
    for i in range(n // 2 - 1, -1, -1):                           # build a max-heap in O(n)
        sift(i, n)
    for end in range(n - 1, 0, -1):
        a[0], a[end] = a[end], a[0]                               # max goes to its final place
        sift(0, end)                                              # repair the shrunken heap

Best-first search: Dijkstra and friends

🔥 Frequently asked
When to useShortest (cheapest) paths on a graph with non-negative weights, or any search where the next state to expand is the lowest-cost one.
Detect it"network delay time" · "cheapest flights" · "path with minimum effort" · "swim in rising water" · "path with maximum probability".
Intuition

Spilling water from a source: it reaches the nearest places first, then spreads further. A priority queue orders the frontier by distance so the next node you finalise is the closest one you have not finished. Because weights are non-negative, nothing found later can be shorter, so a node is final the first time it is popped.

Brute force → optimised

Bellman-Ford relaxes every edge V times: O(V·E). Dijkstra with a heap is O((V + E) log V).

Core idea

dist[src] = 0; push (0, src). Pop (d, u); if d > dist[u] skip (stale). Otherwise relax every edge u → v with weight w: if d + w < dist[v], update and push (dist[v], v). The priority can be any additive or monotone cost (max edge on the path, product of probabilities).

How it works
  1. dist array filled with ∞; dist[src] = 0; heap = [(0, src)].
  2. Pop the smallest (d, u); skip it if it is stale.
  3. For each neighbour v: if d + w < dist[v], set it and push.
  4. Stop early when the target is popped, or run until the heap is empty.

Frequency heaps: reorganise and rank by count

🧊 Secondary
When to useYou must order items so equal ones are separated, or remove the most frequent items first.
Detect it"reorganize string" · "longest happy string" · "reduce array size to half" · "least number of unique integers" · "rearrange so no two adjacent are equal".
Intuition

Seating guests so no two from the same family sit together: always seat someone from the largest remaining family, but never the same family twice in a row. If the biggest family is more than half the seats (rounded up), it is impossible. A max-heap on counts gives the biggest family instantly; holding the family just seated out of the heap for one round enforces the no-repeat rule.

Brute force → optimised

Trying permutations is factorial. Sorting once is not enough because counts change after every placement. The heap re-ranks in O(log k) per step.

Core idea

Max-heap of (count, letter). Pop the top, append it, decrement; keep it out of the heap until the next letter has been placed, then push it back if its count is still positive.

How it works
  1. Count frequencies; push (count, letter) into a max-heap.
  2. Pop the top, append the letter, decrement its count.
  3. Push the previous letter back if it still has copies; hold the current one.
  4. If at the end the string is shorter than the input, return failure.

Rule of thumb

k largest → min-heap of size k; k smallest → max-heap of size k; median → two heaps; sorted sources → k-way merge; weighted shortest path → Dijkstra. If you need arbitrary removal, use lazy deletion or a TreeMap.

Self-test

Answer in your head first, then click to reveal.

Why use a MIN-heap to keep the k largest elements?

Its root is the smallest of the k kept values, so it is exactly the element to evict when a larger one arrives, and it is also the kth largest.

What is the time complexity of heapify, and why is it not O(n log n)?

O(n): most nodes are near the bottom and sift down only a few levels; the work sums to a geometric series.

In the two-heap median, what invariant keeps the median at the tops?

Every element of the max-heap is ≤ every element of the min-heap, and their sizes differ by at most one (low is never smaller).

Why is the heap in a k-way merge never larger than k?

It holds exactly one candidate (the current front) from each non-exhausted list; popping one pushes at most one.

Why does Dijkstra fail with negative edges?

It assumes that when a node is popped its distance is final; a negative edge found later could give a shorter path to an already-finalised node.

What does lazy deletion do and when is the stale item removed?

It leaves an invalid item inside the heap and discards it only when it reaches the top, checked against the source of truth.

Why does PriorityQueue iteration not return sorted order?

A heap only guarantees the root; the array layout is a partial order. Poll repeatedly or sort a copy to get sorted order.

How do you build a max-heap with Python's heapq?

Push negated values (or (−priority, item) tuples) and negate again when reading.

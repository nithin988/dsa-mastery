Advanced Graphs — Pattern Guide

After traversals, graphs get interesting: ordering with dependencies, merging groups, cheapest paths with and without negative weights, spanning trees, fragile points and cycles of mutual reachability. This guide covers topological sort, union-find, Dijkstra, Bellman-Ford and Floyd-Warshall, minimum spanning trees, union-find applications, bridges, strongly connected components and Eulerian paths. Each pattern has the intuition, a step-through animation on a drawn graph, Java and Python code, and a ladder of LeetCode problems.

The mindset

Match the question to the structure: order with dependencies → topological sort; are these connected as things merge → union-find; cheapest path → Dijkstra (non-negative), Bellman-Ford (negative or limited edges), Floyd-Warshall (all pairs); connect everything cheaply → spanning tree; what breaks if I remove this → bridges and articulation points; cycles in a directed graph → strongly connected components; use every edge once → Eulerian path.

Ask these questions on every advanced graph problem:

  • Directed or undirected? Weighted? Can weights be negative?
  • Do I need an order, a path, a tree, or groups?
  • Does the structure change over time (edges added) or is it static? → union-find for merging only.
  • Is it a DAG? → topological order and DP.
  • Do I need all pairs or a single source? → Floyd-Warshall vs Dijkstra / Bellman-Ford.

Topological sort: Kahn's algorithm and DFS

Frequently asked
When to useItems depend on each other (a DAG) and you need a valid order, the order's existence, or the longest dependency chain.
Detect it"course schedule II" · "build order" · "alien dictionary" · "find all possible recipes" · "parallel courses" · "sort with dependencies".
Intuition

Getting dressed: socks before shoes, shirt before jacket. Any item with nothing left to wait for can be done now. Do one, cross it off, and some other items may become free. Repeat. If you run out of free items while some remain, they are waiting on each other in a circle: no valid order exists. The count of unmet prerequisites of a vertex is its in-degree.

Brute force → optimised

Trying all n! orderings is hopeless. Kahn's algorithm finds an order in O(V + E) by always taking a vertex whose in-degree has dropped to 0.

Core idea

Compute indeg[v]. Queue all vertices with indeg == 0. Pop u, append to the order, and for each edge u → v decrement indeg[v]; when it hits 0, enqueue v. If the order has fewer than V vertices there is a cycle. The DFS alternative outputs vertices in reverse finishing order.

How it works
  1. Build adj and indeg.
  2. Queue every vertex with indeg == 0.
  3. Pop u; add it to order; decrement each successor's indeg; enqueue those that reach 0.
  4. order.size() == V ⇒ valid order; otherwise a cycle exists.

Kahn's algorithm (BFS)

List<List<Integer>> g = new ArrayList<>();
int[] indeg = new int[n];
for (int i = 0; i < n; i++) g.add(new ArrayList<>());
for (int[] e : edges) { g.get(e[0]).add(e[1]); indeg[e[1]]++; }          // e[0] must come before e[1]
Queue<Integer> q = new ArrayDeque<>();
for (int i = 0; i < n; i++) if (indeg[i] == 0) q.add(i);
List<Integer> order = new ArrayList<>();
while (!q.isEmpty()) {
    int u = q.poll();
    order.add(u);
    for (int v : g.get(u)) if (--indeg[v] == 0) q.add(v);
}
return order.size() == n ? order : new ArrayList<>();                     // empty = cycle
from collections import deque
g = [[] for _ in range(n)]
indeg = [0] * n
for a, b in edges:                                   # a must come before b
    g[a].append(b)
    indeg[b] += 1
q = deque(i for i in range(n) if indeg[i] == 0)
order = []
while q:
    u = q.popleft()
    order.append(u)
    for v in g[u]:
        indeg[v] -= 1
        if indeg[v] == 0:
            q.append(v)
return order if len(order) == n else []              # empty = cycle

DFS version: reverse post-order

int[] state = new int[n];                              // 0 white, 1 grey, 2 black
Deque<Integer> stack = new ArrayDeque<>();
boolean dfs(int u) {
    state[u] = 1;
    for (int v : g.get(u)) {
        if (state[v] == 1) return false;                   // cycle
        if (state[v] == 0 && !dfs(v)) return false;
    }
    state[u] = 2;
    stack.push(u);                                         // pushed AFTER all its successors
    return true;
}
// for each white u: if (!dfs(u)) return cycle; order = stack from top to bottom
state = [0] * n
post = []
def dfs(u):
    state[u] = 1
    for v in g[u]:
        if state[v] == 1 or (state[v] == 0 and not dfs(v)):
            return False                                  # cycle
    state[u] = 2
    post.append(u)                                        # after all its successors
    return True
ok = all(state[u] != 0 or dfs(u) for u in range(n))
order = post[::-1] if ok else []
Complexity: O(V + E) time, O(V + E) space.
Traps to avoid
  • Edge direction: a → b means a before b. In Course Schedule [a, b] means b before a; reverse accordingly.
  • Always compare order.size() with V to detect cycles.
  • Use a queue for BFS order and a min-heap instead of a queue when the lexicographically smallest order is needed.
  • The topological order is generally not unique.
Variants and follow-ups
  • Longest path in a DAG / parallel courses: process in topological order with dp[v] = max(dp[u] + 1).
  • Alien dictionary: derive edges from adjacent words, then topologically sort letters.
  • Find all possible recipes: ingredients are indegree-0 sources.
When NOT to use

Graphs with cycles (use SCC condensation first) or when only reachability is needed.

Union-Find (disjoint set union)

Frequently asked
When to useElements are repeatedly merged into groups and you ask whether two elements are in the same group.
Detect it"connected components as edges arrive" · "are x and y connected" · "equations x == y" · "swap indices" · "most stones removed" · "number of provinces".
Intuition

Each group has a leader. To find the leader of someone, follow "who is your boss?" up to the top (the root). To merge two groups, make one leader report to the other. Two refinements make it nearly instant: attach the smaller group under the larger (union by size) so chains stay short, and after finding a leader point everyone on the path directly at it (path compression).

Brute force → optimised

Recomputing connectivity with a BFS after every new edge costs O(V + E) each. Union-find answers each query in effectively O(1) (inverse Ackermann).

Core idea

parent[i] = i initially. find(x): climb to the root, compressing the path. union(a, b): find both roots; if equal return false (already connected); else attach the smaller tree under the larger and add sizes. Components = n − successful unions.

How it works
  1. parent[i] = i, size[i] = 1.
  2. find(x): while parent[x] != x: parent[x] = parent[parent[x]], x = parent[x].
  3. union(a, b): ra = find(a), rb = find(b); if ra == rb return false; attach smaller to larger.
  4. Count components by decrementing on each successful union.

Skeleton

union-find with path compression and union by size

class DSU {
    int[] parent, size; int components;
    DSU(int n) {
        parent = new int[n]; size = new int[n]; components = n;
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }
    int find(int x) {
        while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }   // path halving
        return x;
    }
    boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;                         // already in the same set
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra; size[ra] += size[rb]; components--;
        return true;
    }
}
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]     # path halving
            x = self.parent[x]
        return x
    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                                      # already in the same set
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.components -= 1
        return True

Complexity: O(α(n)) ≈ O(1) per operation, O(n) space.
Traps to avoid
  • Always union the roots (find(a), find(b)), not the elements themselves.
  • Without union by size / rank and compression, a chain makes find O(n).
  • union returning a boolean is how you detect cycles and count merges.
  • Map arbitrary keys (strings, coordinates) to integer ids first.
Variants and follow-ups
  • Weighted union-find for ratios (Evaluate Division).
  • Rollback union-find for offline dynamic connectivity.
  • Union-find on grid cells (r * C + c) for islands as land is added.
When NOT to use

Edge deletions (union-find cannot split sets) or when you also need paths between nodes (BFS/DFS).

Dijkstra: weighted shortest paths

Frequently asked
When to useEdges have non-negative costs and you need the cheapest path from a source, or counts of cheapest paths.
Detect it"network delay time" · "cheapest path" · "number of ways to arrive at destination" · "minimum obstacle removal" · "restricted paths".
Intuition

Water spilling from the source along pipes of different lengths: it reaches the nearest junctions first. The next junction to be "reached for good" is the one with the smallest tentative distance, because any other route to it would have to pass through a junction that is farther away already (and weights cannot be negative). After finalising a vertex, check whether going through it shortens its neighbours (relaxation).

Brute force → optimised

Bellman-Ford relaxes every edge V times: O(V·E). With a priority queue ordering vertices by tentative distance, Dijkstra needs O((V + E) log V).

Core idea

dist[src] = 0; heap of (dist, vertex). Pop the smallest; skip if stale (d > dist[u]); for each edge (u, v, w): if d + w < dist[v] update and push. To count shortest paths keep ways[v]: add ways[u] when equal, reset to ways[u] when strictly better.

How it works
  1. Initialise all distances to ∞, source 0, heap with (0, src).
  2. Pop (d, u); ignore it if d > dist[u].
  3. Relax each outgoing edge; push improved neighbours.
  4. Stop when the heap is empty (or the target is popped).

Dijkstra with a path-count and 0-1 BFS variant

long[] dist = new long[n]; Arrays.fill(dist, Long.MAX_VALUE); dist[src] = 0;
long[] ways = new long[n]; ways[src] = 1;
PriorityQueue<long[]> pq = new PriorityQueue<>((a, b) -> Long.compare(a[0], b[0]));
pq.add(new long[]{0, src});
while (!pq.isEmpty()) {
    long[] cur = pq.poll(); long d = cur[0]; int u = (int) cur[1];
    if (d > dist[u]) continue;
    for (int[] e : g[u]) {                                  // e = {v, w}
        long nd = d + e[1];
        if (nd < dist[e[0]]) { dist[e[0]] = nd; ways[e[0]] = ways[u]; pq.add(new long[]{nd, e[0]}); }
        else if (nd == dist[e[0]]) ways[e[0]] = (ways[e[0]] + ways[u]) % MOD;      // another shortest path
    }
}
import heapq
INF = float('inf')
dist = [INF] * n; dist[src] = 0
ways = [0] * n; ways[src] = 1
heap = [(0, src)]
while heap:
    d, u = heapq.heappop(heap)
    if d > dist[u]:
        continue
    for v, w in g[u]:
        nd = d + w
        if nd < dist[v]:
            dist[v], ways[v] = nd, ways[u]
            heapq.heappush(heap, (nd, v))
        elif nd == dist[v]:
            ways[v] = (ways[v] + ways[u]) % MOD                      # another shortest path

0-1 BFS: edge weights are only 0 or 1 (deque instead of a heap)

Deque<int[]> dq = new ArrayDeque<>();
int[] dist = new int[n]; Arrays.fill(dist, Integer.MAX_VALUE); dist[src] = 0;
dq.addFirst(new int[]{src, 0});
while (!dq.isEmpty()) {
    int[] cur = dq.pollFirst(); int u = cur[0];
    if (cur[1] > dist[u]) continue;
    for (int[] e : g[u]) {                                  // e = {v, w}, w is 0 or 1
        if (dist[u] + e[1] < dist[e[0]]) {
            dist[e[0]] = dist[u] + e[1];
            if (e[1] == 0) dq.addFirst(new int[]{e[0], dist[e[0]]});   // free move: front
            else dq.addLast(new int[]{e[0], dist[e[0]]});             // cost 1: back
        }
    }
}
from collections import deque
dist = [float('inf')] * n; dist[src] = 0
dq = deque([src])
while dq:
    u = dq.popleft()
    for v, w in g[u]:                                       # w is 0 or 1
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w
            if w == 0:
                dq.appendleft(v)                            # free move: front
            else:
                dq.append(v)                                # cost 1: back
Complexity: O((V + E) log V) with a binary heap; 0-1 BFS is O(V + E).
Traps to avoid
  • Negative edge weights break the proof: use Bellman-Ford.
  • Skip stale heap entries (d > dist[u]).
  • Use long for distances and for path counts under a modulus.
  • Counting paths: handle the == case and reset on strictly better.
Variants and follow-ups
  • Minimum obstacle removal / min cost of changing arrows: grid with 0/1 edge costs → 0-1 BFS.
  • Restricted paths: Dijkstra from the target, then DP over decreasing distance.
  • Dijkstra with state (position, fuel / stops) when the cost depends on more than the vertex.
When NOT to use

Unweighted graphs (BFS), negative weights (Bellman-Ford), all-pairs (Floyd-Warshall).

Bellman-Ford and Floyd-Warshall

Frequently asked
When to useWeights may be negative, the path may use at most K edges, or you need distances between every pair of vertices.
Detect it"cheapest flights within K stops" · "negative cycle" · "city with the smallest number of neighbours within a threshold" · "all pairs shortest paths" · "transitive closure".
Intuition

Bellman-Ford: a shortest path uses at most V − 1 edges, so after round i every shortest path with at most i edges is correct. Just keep relaxing all edges V − 1 times. Floyd-Warshall: ask for each pair (i, j) whether going through vertex k is cheaper; try k = 0, 1, 2, ... and the table ends up holding all shortest distances (dynamic programming over which intermediate vertices are allowed).

Brute force → optimised

Running Dijkstra from every vertex is O(V·E log V) and fails with negative edges. Floyd-Warshall is O(V³) but trivially simple for small V (≤ 400).

Core idea

Bellman-Ford: repeat V − 1 times: for each edge (u, v, w): dist[v] = min(dist[v], dist[u] + w) (use a copy of the previous round to limit the path to K edges). A V-th round that still improves something proves a negative cycle. Floyd-Warshall: for k: for i: for j: d[i][j] = min(d[i][j], d[i][k] + d[k][j]).

How it works
  1. Bellman-Ford: dist[src] = 0, everything else ∞.
  2. Loop V − 1 times (or K + 1 for at most K stops): relax all edges.
  3. Check one more round: any improvement means a negative cycle.
  4. Floyd-Warshall: initialise d from edges, d[i][i] = 0; triple loop with k outermost.

Floyd-Warshall (all pairs)

int INF = 1_000_000_000;
int[][] d = new int[n][n];
for (int[] row : d) Arrays.fill(row, INF);
for (int i = 0; i < n; i++) d[i][i] = 0;
for (int[] e : edges) { d[e[0]][e[1]] = Math.min(d[e[0]][e[1]], e[2]); d[e[1]][e[0]] = Math.min(d[e[1]][e[0]], e[2]); }
for (int k = 0; k < n; k++)                              // k = allowed intermediate vertex: OUTERMOST loop
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];
INF = float('inf')
d = [[INF] * n for _ in range(n)]
for i in range(n):
    d[i][i] = 0
for u, v, w in edges:
    d[u][v] = min(d[u][v], w)
    d[v][u] = min(d[v][u], w)                            # undirected
for k in range(n):                                       # k = allowed intermediate vertex: OUTERMOST loop
    for i in range(n):
        for j in range(n):
            if d[i][k] + d[k][j] < d[i][j]:
                d[i][j] = d[i][k] + d[k][j]
Complexity: Bellman-Ford O(V·E) time, O(V) space. Floyd-Warshall O(V³) time, O(V²) space.
Traps to avoid
  • For "at most K stops" copy the distance array each round, otherwise a single round can chain several edges.
  • Floyd-Warshall needs k as the outermost loop.
  • Use a sentinel that does not overflow when added (INF = 10⁹ with int, or check for INF).
  • Dijkstra with a plain visited array fails for the K-stops variant; the state needs the stop count.
Variants and follow-ups

Minimum spanning tree: Kruskal and Prim

Frequently asked
When to useYou must connect all vertices with minimum total edge weight (networks, cables, roads).
Detect it"min cost to connect all points" · "minimum spanning tree" · "connect cities / pipes" · "critical and pseudo-critical edges" · "remove edges but keep connectivity".
Intuition

Laying cable between towns with a fixed budget: always build the cheapest link that does not just duplicate a connection you already have. If two towns are already connected (directly or through others), another cable between them is wasted money: skip it. That is Kruskal's rule, and union-find tells you instantly whether two towns are already connected. A spanning tree of V vertices has exactly V − 1 edges.

Brute force → optimised

Trying all subsets of edges is exponential. The greedy choice (cheapest safe edge) is provably optimal for MST (the cut property) and costs O(E log E).

Core idea

Kruskal: sort edges by weight; for each edge union(u, v); if it succeeded add the weight; stop at V − 1 edges. Prim: grow one tree from a start vertex; repeatedly add the cheapest edge leaving the tree using a min-heap.

How it works
  1. Sort edges ascending by weight.
  2. DSU over the vertices.
  3. For each edge: if union merges two different sets → keep it, add its weight.
  4. If fewer than V − 1 edges were kept, the graph is disconnected.

Union-Find applications: cycles, merging and grouping

Secondary
When to useYou add relationships one by one and need to detect redundancy, merge records, or answer queries about equivalence.
Detect it"redundant connection" · "accounts merge" · "evaluate division" · "largest component size by common factor" · "making a large island" · "number of islands II".
Intuition

Adding edges to a forest never forms a cycle as long as each new edge joins two different trees. The first edge whose endpoints already share a root is the one that closes a cycle. The same "already connected?" question detects duplicates in merging problems: if two accounts share an email, union them; the final roots are the merged accounts.

Brute force → optimised

Running a DFS after each added edge to look for a cycle is O(V·(V + E)). With union-find each edge is processed in near-constant time.

Core idea

Create a DSU over ids (map emails, strings or coordinates to integers first). Union related items; the first failing union is the redundant edge. Afterwards group elements by find(x) to read off the merged sets. Weighted DSU stores a ratio to the root for equations like a / b = 2.

How it works
  1. Assign integer ids to the items.
  2. For each relation: union(a, b); if it returns false, record the edge as redundant.
  3. To output groups: bucket every item by find(item).
  4. Weighted DSU: store weight[x] = x / parent[x] and multiply along the path.

Bridges and articulation points (Tarjan low-link)

Secondary
When to useYou need edges (bridges) or vertices (articulation points) whose removal disconnects an undirected graph.
Detect it"critical connections in a network" · "single point of failure" · "articulation point" · "minimum days to disconnect".
Intuition

In the DFS tree, a subtree hangs below an edge. If some vertex in that subtree has a back edge to the parent's side (an ancestor), the subtree is also connected the other way round, so cutting the tree edge does not disconnect it. If the subtree can climb no higher than its own top vertex, the tree edge is the only link: a bridge. low[v] is the smallest discovery time that the subtree of v can reach with at most one back edge.

Brute force → optimised

Remove each edge and test connectivity: O(E·(V + E)). Tarjan's low-link DFS finds all bridges in O(V + E).

Core idea

DFS with disc[u] (discovery time) and low[u]. For each neighbour v ≠ parent: if visited, low[u] = min(low[u], disc[v]) (back edge); else recurse and set low[u] = min(low[u], low[v]). Tree edge (u, v) is a bridge iff low[v] > disc[u]. Articulation point u: low[v] ≥ disc[u] for some child v (non-root), or the root has ≥ 2 DFS children.

How it works
  1. disc, low arrays, timer.
  2. Enter u: disc[u] = low[u] = ++timer.
  3. Skip the parent; visited neighbour → update low with disc; unvisited → recurse then update low with the child's low.
  4. After the child: low[v] > disc[u] ⇒ bridge.

Strongly connected components (Kosaraju / Tarjan)

Secondary
When to useA directed graph has cycles and you need its mutually reachable groups, or the structure that remains after contracting them.
Detect it"strongly connected" · "longest cycle in a graph" · "maximum employees invited" · "eventual safe nodes" · 2-SAT style dependencies.
Intuition

In a directed graph, two vertices are in the same strongly connected component (SCC) if each can reach the other. Contract every SCC into one node and all cycles disappear: the result is a DAG. Kosaraju's trick: vertices that finish last in a DFS lie in a source SCC; running a DFS from them in the reversed graph cannot escape their own SCC, so each reversed DFS tree is exactly one SCC.

Brute force → optimised

Testing mutual reachability for every pair is O(V·(V + E)). Kosaraju or Tarjan find all SCCs in O(V + E).

Core idea

Kosaraju: (1) DFS the graph, push vertices on a stack when they finish. (2) Build the reversed graph. (3) Pop vertices from the stack; DFS in the reversed graph from each unvisited one; the visited set is one SCC.

How it works
  1. Pass 1: DFS over all vertices, record finishing order.
  2. Reverse all edges.
  3. Pass 2: for vertices in decreasing finishing time, DFS on the reversed graph; each DFS collects one SCC.
  4. Optional: build the condensation DAG (edges between SCC ids).

Deque<Integer> order = new ArrayDeque<>();
int[] comp;

void dfs1(int u) { seen[u] = true; for (int v : g[u]) if (!seen[v]) dfs1(v); order.push(u); }   // push AFTER children
void dfs2(List<Integer>[] rev, int u, int id) { seen[u] = true; comp[u] = id; for (int v : rev[u]) if (!seen[v]) dfs2(rev, v, id); }

int kosaraju() {                                             // returns the number of SCCs; comp[u] = its component id
    seen = new boolean[n];
    for (int u = 0; u < n; u++) if (!seen[u]) dfs1(u);
    List<Integer>[] rev = new List[n];                       // reversed graph
    for (int i = 0; i < n; i++) rev[i] = new ArrayList<>();
    for (int u = 0; u < n; u++) for (int v : g[u]) rev[v].add(u);
    Arrays.fill(seen, false);
    comp = new int[n];
    int sccCount = 0;
    while (!order.isEmpty()) { int u = order.pop(); if (!seen[u]) dfs2(rev, u, sccCount++); }    // latest finisher first

Eulerian paths: Hierholzer's algorithm

Secondary
When to useYou must traverse every edge exactly once (an itinerary, a de Bruijn sequence, arranging pairs).
Detect it"reconstruct itinerary" · "valid arrangement of pairs" · "cracking the safe" · "use all tickets exactly once" · "Eulerian path / circuit".
Intuition

Imagine walking along one-way roads and spraying a mark on each road you use. Keep walking along unused roads until you are stuck: the place where you are stuck must be the end of the whole trip. Write that place at the end of your route, step back one vertex, and if it still has unused roads, follow them as a detour. Because routes are assembled backwards, reversing the list at the end gives the full trip.

Brute force → optimised

Trying all orderings of edges is factorial. Hierholzer uses each edge once: O(E) (or O(E log E) when neighbours must be visited in sorted order).

Core idea

dfs(u): while u has an unused outgoing edge u → v: remove that edge and dfs(v). Then append u to route. Finally reverse route. A directed Eulerian path exists iff in/out degrees balance (one vertex with out − in = 1, one with in − out = 1, others equal) and the edges are connected.

How it works
  1. Build adjacency lists (sorted for the lexicographically smallest itinerary).
  2. Start at the start vertex (the one with out − in = 1, or any vertex for a circuit).
  3. dfs(u): consume edges while any remain; recurse along each.
  4. Append u after its edges are exhausted; reverse the route.

Rule of thumb

dependencies → topological sort; merging groups → union-find; weighted paths → Dijkstra unless negative / limited edges / all pairs; connect everything → MST; single points of failure → bridges; directed cycles → SCC.

Self-test

Answer in your head first, then open the question to reveal the answer.

How does Kahn's algorithm detect a cycle?

If fewer than V vertices are output, the remaining ones always have a pending prerequisite inside the remaining set, so they lie on or behind a cycle.

What do union by size and path compression each achieve?

Union by size keeps trees shallow (height O(log n)); path compression flattens the path after each find. Together they give amortised inverse-Ackermann time per operation.

Why does Dijkstra require non-negative weights?

It assumes a popped vertex's distance is final; a later negative edge could create a shorter path to an already finalised vertex.

How does Bellman-Ford limit the path to at most K edges?

Run only K rounds, and in each round relax using a copy of the previous round's distances so one round adds at most one edge.

Why is k the outermost loop in Floyd-Warshall?

After processing intermediate vertices 0..k the table is correct for paths using only those intermediates; each stage builds on the previous complete stage.

State the Kruskal rule and why it works.

Add the cheapest edge that connects two different components; by the cut property the cheapest edge crossing any cut belongs to some MST, so the greedy choice is safe.

What does low[v] > disc[u] mean for the tree edge (u, v)?

The subtree of v cannot reach u or any ancestor through a back edge, so removing the edge disconnects v's subtree: it is a bridge.

Why is the Eulerian route built in reverse in Hierholzer's algorithm?

A vertex is appended only when all its edges are used; the first vertex stuck is the true end of the trip, and detours are spliced in before it, so the list is the route backwards.

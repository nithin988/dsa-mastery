Sorting and Intervals — Pattern Guide

Sorting is rarely the final answer; it is the move that makes the real answer easy. This guide covers the sorts you must know, custom comparators, counting and bucket sort, and the interval toolbox: merging, inserting, sweep line and greedy scheduling, plus sorting as preprocessing and cyclic sort. Each pattern has the intuition, a step-through animation, Java and Python code, and a ladder of LeetCode problems.

The mindset

Sorting costs O(n log n) once and then buys you order: neighbours are the closest, ends are the extremes, overlaps become adjacent. For interval problems the two decisions are almost always the same: what do I sort by (start for merging and inserting, end for greedy selection) and what do I track while scanning (the last end, a running count, a heap of end times).

Ask these questions on every sorting or interval problem:

  • Will sorting make the answer easier? → pairs of extremes, adjacent differences, matching two lists.
  • Do I sort by start or by end? → start to merge/insert; end to select the maximum number.
  • Is the range of values small? → counting or bucket sort in O(n).
  • Do I need the number of overlaps? → sweep line (+1 / −1 events) or a heap of end times.
  • Are the values exactly 1..n? → cyclic sort with O(1) space.

Comparison sorts: merge, quick and what to pick

🔥 Frequently asked
When to useYou are asked to implement a sort, to merge sorted data, or to count inversions during a sort.
Detect it"sort an array" · "merge two sorted arrays" · "count smaller numbers after self" · "reverse pairs" · "stable sort needed".
Intuition

Merge sort is how you would sort a deck of cards with a friend: split it in two, each sorts their half, then you interleave the two sorted piles by always taking the smaller top card. Interleaving two sorted piles is cheap (one pass), and halving gives only log n rounds. Quick sort instead picks a pivot and throws smaller cards left, larger right.

Brute force → optimised

Insertion or bubble sort compares nearly every pair: O(n²). Any comparison sort needs at least n log n comparisons; merge sort reaches it in every case.

Core idea

Merge sort: sort(left), sort(right), merge. The merge step is a two-pointer walk over two sorted runs. Quick sort: partition around a pivot, recurse on both sides (average O(n log n), worst O(n²) without a random pivot).

How it works
  1. Base case: 0 or 1 elements are sorted.
  2. Split at mid; recursively sort both halves.
  3. Merge: two pointers i, j; copy the smaller (<= keeps it stable) into a temp array.
  4. Copy the temp back (or return the merged list).

Skeleton

merge sort

void mergeSort(int[] a, int[] tmp, int lo, int hi) {
    if (lo >= hi) return;
    int mid = (lo + hi) >>> 1;
    mergeSort(a, tmp, lo, mid);
    mergeSort(a, tmp, mid + 1, hi);
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];   // <= keeps it stable
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi) tmp[k++] = a[j++];
    System.arraycopy(tmp, lo, a, lo, hi - lo + 1);
}
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:                      # <= keeps it stable
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]
Skeleton

quick sort with a random pivot

void quickSort(int[] a, int lo, int hi) {
    if (lo >= hi) return;
    int r = lo + (int) (Math.random() * (hi - lo + 1));
    swap(a, r, hi);                                   // random pivot avoids the sorted-input worst case
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; j++) if (a[j] < pivot) swap(a, i++, j);
    swap(a, i, hi);
    quickSort(a, lo, i - 1);
    quickSort(a, i + 1, hi);
}
import random
def quick_sort(a, lo, hi):
    if lo >= hi:
        return
    r = random.randint(lo, hi)
    a[r], a[hi] = a[hi], a[r]                         # random pivot avoids the sorted-input worst case
    pivot, i = a[hi], lo
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    quick_sort(a, lo, i - 1)
    quick_sort(a, i + 1, hi)

merge sorted array into the front array (fill from the back)

int i = m - 1, j = n - 1, k = m + n - 1;

    else:

    k -= 1
⏱ Complexity — Merge sort O(n log n) time, O(n) space. Quick sort O(n log n) average, O(n²) worst, O(log n) stack.
Traps to avoid
  • Quick sort on already-sorted input with a fixed pivot is O(n²): randomise or use median-of-three.
  • (lo + hi) / 2 can overflow: use lo + (hi − lo) / 2 or >>> 1.
  • Stability matters when sorting records by one key after another; use <= in the merge.
  • Merging in place from the back avoids overwriting unread elements.
Variants and follow-ups
  • Count inversions or reverse pairs: count cross-half pairs just before merging.
  • Sort a linked list: merge sort needs no extra array.
  • External sort: sort chunks that fit in memory, then k-way merge with a heap.
When NOT to use

Small integer ranges (counting sort), nearly sorted data (insertion sort / TimSort), or when you only need the k-th element (quick select).

Custom comparators and multi-key sorting

🔥 Frequently asked
When to useThe natural order is not the order you want: concatenation order, by frequency then alphabet, by height then position.
Detect it"arrange to form the largest" · "sort by … then by …" · "reconstruct queue" · "rank teams" · "custom order".
Intuition

A comparator answers one question for any two items: who goes first? If that answer is consistent (a proper ordering), any sort algorithm will arrange the whole list. For "largest number" you cannot compare 3 and 30 numerically, but you can ask which concatenation is bigger: "330" vs "303".

Brute force → optimised

Trying all permutations is O(n!). Finding a valid comparator reduces it to one sort: O(n log n).

Core idea

Write compare(a, b) returning negative if a should come first. It must be transitive and consistent. For multiple keys, compare the first key and fall back to the next on ties.

How it works
  1. Decide the rule that puts a before b.
  2. Check it is a strict weak order (transitive, consistent for ties).
  3. Sort with the comparator (or a key function).
  4. Post-process (join, insert at index, strip zeros).

  • Sort by frequency then value: key=(count, value).
  • Custom alphabet (alien dictionary): map each letter to its rank and compare rank tuples.
  • Sort intervals by start, or by end for greedy (patterns 4 and 7).
When NOT to use

When a simple key (one number or string) already gives the order; do not over-engineer a comparator.

Counting and bucket sort (beating n log n)

🔥 Frequently asked
When to useValues or frequencies lie in a small known range, so you can use them directly as array indices.
Detect it"top K frequent" · "sort colors / ages / scores in 0..100" · "h-index" · "sort characters by frequency" · values up to ~10⁶.
Intuition

Sorting library books by shelf number is easier than comparing titles: just drop each book in the box labelled with its shelf, then read the boxes in order. Bucket sort uses the key as the box number. Frequencies are ideal keys: no element appears more than n times, so there are only n boxes.

Brute force → optimised

Sorting the entries by count is O(n log n). Placing each value in bucket[frequency] and scanning from the highest bucket down is O(n).

Core idea

Count occurrences, then place items in an array of buckets indexed by count (or by value for counting sort). Read the buckets in the order you need.

How it works
  1. Count: cnt[x]++ (hash map or array).
  2. Create buckets[0..n]; put each value x into buckets[cnt[x]].
  3. Scan buckets from high to low, collecting until you have k items.
  4. Counting sort: walk values 0..max and output each value cnt[v] times.

counting sort for small integer ranges (sort colors)

int[] count = new int[3];

⏱ Complexity — O(n + k) time, O(n + k) space for range size k.
Traps to avoid
  • Only valid when keys are small, non-negative integers (or can be shifted into that range).
  • Counting sort is stable only if you place elements from the back using prefix sums.
  • Top K with ties: decide whether to return all tied items or exactly k.
  • A heap of size k is O(n log k) and handles streaming input; buckets need all data first.
Variants and follow-ups
  • H-index: buckets[min(citations, n)], then scan from high to low.
  • Radix sort: counting sort digit by digit, O(d·(n + b)).
  • Maximum gap: bucket by value range; the answer lies between buckets.
When NOT to use

Large or unbounded key ranges (use comparison sort) or streaming data where the full count is unknown.

Merging intervals

🔥 Frequently asked
When to useCombine overlapping ranges, find union length, or intersect two interval lists.
Detect it"merge intervals" · "overlapping" · "union of ranges" · "summary ranges" · "interval list intersections".
Intuition

Imagine laying coloured strips on a ruler. Once the strips are sorted by their left end, the only strip a new one can overlap is the latest strip you placed (everything earlier ends before it). So you either stretch that last strip or put a new strip down.

Brute force → optimised

Compare every pair of intervals and union overlaps repeatedly: O(n²) or worse. Sorting by start turns it into one linear scan after an O(n log n) sort.

Core idea

Sort by start. Keep a result list. For each interval: if it starts after the last merged interval ends → append; otherwise extend the last interval's end to max(end, cur.end).

How it works
  1. Sort intervals by start.
  2. Put the first interval in merged.
  3. For each next interval: if start > last.end append it, else last.end = max(last.end, end).
  4. Return merged.

⏱ Complexity — O(n log n) time (sorting), O(n) space for the output.
Traps to avoid
  • Decide whether touching intervals ([1,4], [4,5]) merge: usually yes (<=).
  • Extend with max(last.end, end): a later interval can be fully inside the last one.
  • In Java, mutate a copy or the sorted array's inner arrays carefully; they are shared objects.
  • Do not forget to sort, or the single-pass logic is wrong.
Variants and follow-ups
  • Summary ranges on a sorted array: group consecutive numbers.
  • Count ways to group overlapping ranges: number of merged groups g → 2^g.
  • Employee free time: merge all schedules, take the gaps.
When NOT to use

Intervals that arrive online with queries in between (use a balanced tree / TreeMap).

Insert into a sorted interval list; calendar booking

🔥 Frequently asked
When to useIntervals are already sorted and disjoint, and you add one (or many, online) while keeping the invariant.
Detect it"insert interval" · "my calendar" · "data stream as disjoint intervals" · "range module".
Intuition

A shelf of sorted, non-touching books and a new book to insert. Slide past every book that ends before the new one starts. Then, while books overlap the new one, absorb them (stretch the new book to cover them). Finally put the new book down and copy the remaining books.

Brute force → optimised

Append the new interval and re-run merge intervals: O(n log n). Because the list is already sorted, one linear pass in three phases is O(n).

Core idea

Three loops over the same index: (1) iv[i].end < new.start → copy; (2) iv[i].start <= new.end → merge into new; (3) copy the rest. For online insertion keep a TreeMap keyed by start and use floorKey / ceilingKey for neighbours.

How it works
  1. Copy all intervals that end before new.start.
  2. While iv[i].start <= new.end: new.start = min, new.end = max; i++.
  3. Add new.
  4. Copy the rest.

        self.s = []                                               # sorted (start, end)
    def book(self, start, end):

Sweep line: counting overlaps over time

🔥 Frequently asked
When to useYou need the maximum number of simultaneous intervals, or a total over time (rooms, platforms, capacity).
Detect it"minimum meeting rooms" · "car pooling" · "maximum concurrent" · "skyline" · "my calendar III" · "minimum platforms".
Intuition

Stand at the door and count: every time someone walks in add one, every time someone walks out subtract one. If you list all the entrances and exits in time order, the running count tells you how many are inside at every moment, and the biggest value is the number of rooms you need.

Brute force → optimised

Check the overlap count at every possible time: O(n × range). Sorting the 2n events and sweeping once is O(n log n).

Core idea

Convert each [start, end) to events (start, +1) and (end, −1). Sort by time, with ends before starts at equal times (the room is free the moment the old meeting ends). Sweep keeping a running sum and its maximum. Alternative: sort starts and ends separately and use two pointers; or use a min-heap of end times.

How it works
  1. Create events (time, +1/−1).
  2. Sort by time; at ties put −1 first.
  3. Sweep: active += delta; peak = max(peak, active).
  4. Return peak (rooms) or check active ≤ capacity at every step.

Greedy interval scheduling

🔥 Frequently asked
When to useSelect the maximum number of non-overlapping intervals, or the minimum removals or points needed to cover/pierce all.
Detect it"non-overlapping intervals" · "minimum arrows to burst balloons" · "maximum events attended" · "longest chain of pairs" · "partition labels".
Intuition

You are choosing which meetings to attend in one room. The meeting that ends earliest leaves the most time for everything after it, so taking it can never be worse than taking a longer one that starts at the same place. Repeat on what remains. That is the exchange argument: swap any optimal solution's first meeting for the earliest-ending one and nothing gets worse.

Brute force → optimised

Try every subset of intervals: O(2ⁿ). A DP over sorted intervals is O(n²) or O(n log n). The greedy gets O(n log n) with a single scan.

Core idea

Sort by end. Keep lastEnd. For each interval: if start >= lastEnd keep it and update lastEnd; otherwise it overlaps, so count it as removed (or skip). Balloons: one arrow bursts everything sharing a point, so count a new arrow when start > lastEnd.

How it works
  1. Sort by end (ascending).
  2. lastEnd = −∞, kept = 0.
  3. For each interval: if start >= lastEnd → keep, lastEnd = end.
  4. Removed = n − kept.

  • Weighted job scheduling: DP + binary search (greedy fails with weights).

Sort first, then two pointers or neighbours

🔥 Frequently asked
When to usePairing smallest with largest, matching two lists, or the answer depends on adjacent elements in sorted order.
Detect it"boats to save people" · "assign cookies" · "minimum difference" · "largest perimeter triangle" · "two city scheduling" · "array partition".
Intuition

Once data is sorted, the extremes sit at the ends and the closest values sit side by side. To fit people into 2-seat boats, the heaviest person is the hardest to place, so give them the lightest partner that fits; if even the lightest does not fit, they travel alone. Sorting turns "who goes with whom" into walking two pointers inward.

Brute force → optimised

Trying every pairing is O(n²) or worse. After sorting, one linear two-pointer pass decides everything.

Core idea

Sort, then either use l and r at the ends (pair extremes), or scan adjacent elements (minimum difference, duplicates, triangle sides), or use a greedy that processes in sorted order.

How it works
  1. Sort the array (or both arrays).
  2. Choose the pass: opposite ends, adjacent pairs, or matching two sorted lists.
  3. Apply the greedy rule at each step and move pointers.
  4. Count or accumulate the answer.

Cyclic sort: use the index as the hash

🧊 Secondary
When to useAn array of size n holds numbers from 1..n (possibly with duplicates and gaps) and you must find missing or repeated values.
Detect it"missing number" · "find all duplicates" · "set mismatch" · "first missing positive" · values within [1, n].
Intuition

Seat numbered guests at a table with n numbered chairs: guest x should sit in chair x. Walk along and whenever a guest is in the wrong chair, swap them toward their own chair. When every guest who can be seated is seated, any chair holding the wrong guest points straight at the missing or duplicated number.

Brute force → optimised

Use a hash set or boolean array: O(n) extra space. Cyclic sort rearranges the input array itself, so the extra space is O(1).

Core idea

For each index i: while a[i] is in 1..n and a[a[i] − 1] != a[i], swap a[i] into its home. Each swap sends one value to its final place, so total swaps ≤ n. Afterwards, scan for a[i] != i + 1.

How it works
  1. i = 0.
  2. While a[i] is in range and its home does not already hold it: swap a[i] with a[a[i] − 1].
  3. Otherwise i++.
  4. Scan: the first i with a[i] != i + 1 gives the missing number i + 1 (and a[i] is a duplicate).

Self-test

Answer in your head first, then click to reveal.

Why is merge sort stable and what keeps it stable?

Taking from the left run when left[i] <= right[j] keeps equal elements in their original relative order.

Why must non-overlapping-interval greedy sort by end, not start?

The interval that ends earliest leaves the most room for later ones. Sorting by start can pick a long interval that blocks many short ones.

In the sweep line, why process end events before start events at the same time?

For half-open intervals [s, e), a meeting ending at time t has already freed its room when another starts at t.

When can bucket sort run in O(n)?

When keys lie in a known, small range (for example frequencies 1..n or ages 0..120), so each key maps directly to a bucket.

How does Insert Interval stay O(n) when the list is sorted?

Intervals before the new one are copied, overlapping ones are absorbed in one scan, and the rest are copied, so each interval is touched once.

Why does a comparator like (a, b) -> a − b risk bugs?

Subtraction overflows for extreme values; use Integer.compare.

What does cyclic sort guarantee after the swapping loop?

Every value in 1..n that appears is at index value − 1, so any index with the wrong value reveals a missing number.

What is the worst case of quick sort and how do you avoid it?

O(n²) when pivots are always the smallest or largest (for example sorted input with a fixed pivot). Randomise the pivot or use median-of-three.

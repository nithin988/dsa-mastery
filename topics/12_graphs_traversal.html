Graph Traversal — Pattern Guide

Graphs model almost everything: maps, social networks, grids, puzzles, dependencies. This guide covers representing graphs, DFS and connected components, BFS shortest paths, grids and islands, multi-source BFS, cycle detection, bipartite checking, implicit state graphs and border-first search. Each pattern has the intuition, a step-through animation that draws the graph or grid, Java and Python code, and a ladder of LeetCode problems.

How to use this page

For each section: read Detect and Intuition, play the animation, then try to write the skeleton from memory before opening the code. Finish by solving the problem ladder in order.

The mindset

Every graph problem has two decisions: how to model it (what is a vertex, what is an edge, is the graph given or implicit?) and which traversal fits (DFS to explore, count and detect cycles; BFS for fewest steps and levels). Mark vertices visited the moment you discover them, start from every unvisited vertex when the graph may be disconnected, and remember that grids and puzzles are graphs in disguise.

Ask these questions on every graph problem:

  • What are the vertices and the edges? (cells, words, states, courses)
  • Directed or undirected? Weighted or not? (weights → Dijkstra, topic 13)
  • Do I need fewest steps? → BFS. Count, explore, detect a cycle? → DFS.
  • Can the graph be disconnected? → loop over all vertices.
  • Is there more than one starting point? → multi-source BFS.

Graph basics: modelling and representation

Frequently asked
When to useThe problem describes relationships between things: friends, roads, prerequisites, links.
Detect it"n nodes and a list of edges" · "connected" · "path exists" · "prerequisites" · "network" · "town judge" · grids and word games that hide a graph.
Intuition

A graph is just a table of who is connected to whom. Choose the table that makes the question you ask most often cheap. "Who are the neighbours of u?" is by far the most common, so you keep a list of neighbours for each vertex (adjacency list). A matrix answers "is there an edge u–v?" in O(1) but wastes O(V²) space on sparse graphs.

Brute force → optimised

Scanning the whole edge list to find the neighbours of a vertex costs O(E) each time, O(V·E) for a traversal. An adjacency list makes it O(deg(u)), and a full traversal O(V + E).

Core idea

Build adj[u] from the edge list once. Undirected edge → add both directions; directed → one. Weighted → store (v, w) pairs. For grids and implicit state spaces, generate neighbours on the fly instead of storing them.

How it works
  1. Count vertices n (watch 0- vs 1-indexing).
  2. Create n empty lists.
  3. For each edge (u, v): adj[u].add(v); if undirected also adj[v].add(u).
  4. Keep a visited set/array for traversals; compute in-degree / out-degree if the problem is about counts.

degrees: find the town judge (trusts nobody, trusted by everyone else)

int[] score = new int[n + 1];

    score[a] -= 1                                           # out-edge counts -1

    if score[i] == n - 1:
        return i

Complexity: Build: O(V + E) time and space. Matrix: O(V²) space.
Traps to avoid
  • Vertices numbered from 1 need an array of size n + 1.
  • Undirected means two adjacency entries per edge; forgetting one makes the graph look directed.
  • Duplicate edges and self-loops may appear: decide whether they matter.
  • A disconnected graph needs the traversal started from every unvisited vertex.
Variants and follow-ups
  • Adjacency matrix when n ≤ 500 and the input is a matrix (number of provinces).
  • Edge list for algorithms that sort edges (Kruskal).
  • Indegree array for topological sort and for "vertices that reach all nodes" (indegree 0).
When NOT to use

If the input is already a grid, do not build a list: compute (r ± 1, c ± 1) neighbours directly.

DFS and connected components

Frequently asked
When to useYou must visit everything reachable from a vertex, count groups, or explore one path at a time.
Detect it"number of provinces / connected components" · "can reach all rooms" · "clone a graph" · "is there a path" · "number of operations to connect the network".
Intuition

Exploring a maze with chalk: walk down a corridor, marking each junction you pass; at a dead end (or an already-marked junction) turn back to the most recent junction with an unexplored branch. The chalk marks (the visited set) guarantee you never go round in circles. Starting a fresh walk from any unmarked spot counts the separate parts of the maze.

Brute force → optimised

Checking every pair of vertices for a path is O(V²·(V + E)). One DFS marks the entire component of its start vertex in O(V + E), and each vertex is processed once overall.

Core idea

dfs(u): mark u visited; for each neighbour v not visited: dfs(v). For components: loop over all vertices and start a DFS from each unvisited one, counting the starts. Use an explicit stack when the depth may be large.

How it works
  1. visited = {}.
  2. For every vertex u: if not visited → components++, dfs(u).
  3. dfs(u): mark, then recurse on unvisited neighbours.
  4. Total work O(V + E): every vertex once, every edge looked at once (twice if undirected).

DFS: recursive, iterative, and counting components

List<List<Integer>> g;                          // adjacency list
boolean[] seen;

void dfs(int u) {
    seen[u] = true;
    for (int v : g.get(u)) if (!seen[v]) dfs(v);
}
int countComponents(int n) {
    seen = new boolean[n];
    int components = 0;
    for (int u = 0; u < n; u++) if (!seen[u]) { components++; dfs(u); }
    return components;
}

// iterative: avoids stack overflow on long paths
void dfsIterative(int start) {
    Deque<Integer> st = new ArrayDeque<>();
    st.push(start); seen[start] = true;
    while (!st.isEmpty()) {
        int u = st.pop();
        for (int v : g.get(u)) if (!seen[v]) { seen[v] = true; st.push(v); }
    }
}

clone a graph (map original → copy)

Map<Node, Node> copy = new HashMap<>();
Node clone(Node n) {
    if (n == null) return null;
    if (copy.containsKey(n)) return copy.get(n);              // already cloned: reuse (breaks cycles)
    Node c = new Node(n.val);
    copy.put(n, c);                                           // register BEFORE recursing
    for (Node nb : n.neighbors) c.neighbors.add(clone(nb));
    return c;
}
copy = {}
def clone(n):
    if not n:
        return None
    if n in copy:
        return copy[n]                                        # already cloned: reuse (breaks cycles)
    c = Node(n.val)
    copy[n] = c                                               # register BEFORE recursing
    c.neighbors = [clone(nb) for nb in n.neighbors]
    return c
Complexity: O(V + E) time, O(V) space (visited set + recursion / stack).
Traps to avoid
  • Mark a vertex visited when you push or enter it, not when you leave it, or cycles loop forever.
  • For undirected graphs do not treat the edge back to the parent as a cycle.
  • Deep recursion (10⁵ vertices in a path) overflows the stack: use the iterative version.
  • Clone Graph: put the new node in the map before cloning the neighbours.
Variants and follow-ups
  • Keys and rooms: DFS from room 0, check all rooms visited.
  • Number of operations to connect the network: components − 1 cables are needed (and enough spare edges).
  • Number of provinces on an adjacency matrix: same count with isConnected[u][v].
When NOT to use

Shortest paths in unweighted graphs (BFS finds them; DFS does not).

BFS and shortest paths in unweighted graphs

Frequently asked
When to useThe answer is a minimum number of edges or moves, or you need all vertices at distance exactly d.
Detect it"minimum number of steps / moves / edges" · "shortest path in a maze or grid" · "nearest exit" · "reach in the fewest jumps".
Intuition

Ripples in a pond: the water reaches everything at distance 1 before anything at distance 2. A queue reproduces this: vertices at distance d are dequeued before any at distance d + 1. The first time a vertex is discovered it is therefore by a shortest path, so you never have to revisit it.

Brute force → optimised

Enumerating all paths with DFS is exponential. BFS reaches each vertex once: O(V + E), and the distance array it fills is exactly the shortest-path lengths.

Core idea

dist[src] = 0, enqueue src. While the queue is not empty: pop u; for each neighbour v with dist[v] == −1: dist[v] = dist[u] + 1, parent[v] = u, enqueue v. Rebuild a path by following parent back from the target.

How it works
  1. dist filled with −1; dist[src] = 0; queue = [src].
  2. Pop u.
  3. For each unvisited neighbour: set its distance and parent; enqueue it.
  4. Stop when the target is dequeued (or the queue empties).

jump game III: BFS over positions

boolean canReach(int[] a, int start) {
    Queue<Integer> q = new ArrayDeque<>(); q.add(start);
    boolean[] seen = new boolean[a.length]; seen[start] = true;
    while (!q.isEmpty()) {
        int i = q.poll();
        if (a[i] == 0) return true;
        for (int j : new int[]{i + a[i], i - a[i]})
            if (j >= 0 && j < a.length && !seen[j]) { seen[j] = true; q.add(j); }
    }
    return false;
}
def can_reach(a, start):
    q, seen = deque([start]), {start}
    while q:
        i = q.popleft()
        if a[i] == 0:
            return True
        for j in (i + a[i], i - a[i]):
            if 0 <= j < len(a) and j not in seen:
                seen.add(j)
                q.append(j)
    return False
Complexity: O(V + E) time, O(V) space.
Traps to avoid
  • Mark vertices visited when you enqueue them, not when you dequeue them.
  • BFS gives shortest paths only when every edge has the same cost; weighted graphs need Dijkstra.
  • Stop early when the target is found to save work.
  • For levels, process queue.size() vertices per round.
Variants and follow-ups
  • Shortest path with alternating edge colours: state = (vertex, last colour).
  • Minimum Height Trees: peel leaves layer by layer (BFS from the outside in).
  • Bidirectional BFS from both ends for huge branching factors.
When NOT to use

Weighted edges (Dijkstra / 0-1 BFS), or when you must list every path (DFS).

Grids as graphs: islands and flood fill

Frequently asked
When to useA 2D grid where connected cells of the same kind form regions to count, measure or colour.
Detect it"number of islands" · "max area of island" · "flood fill" · "island perimeter" · "count sub-islands" · "making a large island".
Intuition

A grid is a graph you do not have to store: the neighbours of (r, c) are (r ± 1, c) and (r, c ± 1). Scan the cells; each time you find land you have not seen, you have discovered a new island, so flood it (DFS or BFS) to mark all of it and never count it again. "Sinking" the land (changing 1 to 0) doubles as the visited marker.

Brute force → optimised

Comparing every pair of land cells for connectivity is O((mn)²). A single flood fill per island touches each cell once: O(m·n) overall.

Core idea

for r, c: if grid[r][c] == 1: count++; dfs(r, c). dfs returns immediately for out-of-bounds, water or already visited; otherwise it marks the cell and recurses to 4 neighbours. For area, return 1 + sum of the four calls.

How it works
  1. Scan every cell.
  2. On unvisited land: increment the island count and start a flood fill.
  3. Flood fill: bounds check, land check, mark visited, recurse in 4 directions.
  4. Measure by returning sizes; compute perimeter by counting land–water boundaries.

When NOT to use

Shortest paths on the grid (BFS) or weighted movement (Dijkstra).

Multi-source BFS: waves from many starting points

Frequently asked
When to useYou need each cell's distance to the nearest source, or something spreads from several places at once.
Detect it"distance to the nearest 0 / gate / land / water" · "rotting oranges" · "spread of fire" · "map of highest peak" · "as far from land as possible".
Intuition

Many stones dropped into a pond at the same moment: the ripples spread together, and each point of water is first reached by the stone nearest to it. Instead of running a separate BFS from every cell, begin with all sources at distance 0 in the same queue. The wave then advances one step at a time and the first time a cell is reached, that distance is its answer.

Brute force → optimised

A BFS from every cell costs O((mn)²). One BFS from all sources costs O(m·n) because each cell enters the queue once.

Core idea

Initialise the queue with every source and set their distance to 0 (or 'visited'). Standard BFS afterwards. Process by levels when you need the number of rounds (minutes).

How it works
  1. Scan the grid; enqueue all sources, set their distance 0.
  2. BFS: pop a cell, for each unvisited neighbour set dist = dist[cell] + 1, enqueue.
  3. Rounds (levels) equal elapsed time for spreading problems.
  4. Unreached cells keep their sentinel (−1) → impossible case.

Cycle detection with DFS colours

Frequently asked
When to useYou must know whether a directed graph is acyclic, or find vertices that cannot reach a cycle.
Detect it"can you finish all courses" · "detect a cycle" · "eventual safe states" · "deadlock" · "circular dependency".
Intuition

Walking a path of chalk-marked rooms: grey rooms are on the path you are currently walking, black rooms are fully explored, white rooms are untouched. If an exit from your current room leads to a grey room, you have walked in a circle. A black room is harmless: everything beyond it was already explored and led nowhere back to you.

Brute force → optimised

Checking reachability from every vertex to itself is O(V·(V + E)). One DFS with three states finds a cycle in O(V + E).

Core idea

state[u]: 0 white, 1 grey (in the recursion stack), 2 black (done). dfs(u): set grey; for each v: if grey → cycle; if white and dfs(v) finds a cycle → cycle; then set black. For undirected graphs, ignore the edge back to the parent.

How it works
  1. All vertices white.
  2. Enter u: colour grey.
  3. For each neighbour: grey → return cycle; white → recurse.
  4. Leaving u: colour black.

Bipartite check: two-colouring

Secondary
When to useYou must divide vertices into two sets so that every edge connects different sets (teams, rooms, conflicts).
Detect it"is graph bipartite" · "possible bipartition" · "dislikes" · "split into two groups with no conflicts" · "assign two colours".
Intuition

Painting a map with only two colours so that neighbours always differ. Pick any vertex and paint it red; all its neighbours must be blue; their neighbours red again, and so on. If you ever reach a neighbour that already has the same colour as you, no two-colouring exists, and that happens exactly when the graph has a cycle of odd length.

Brute force → optimised

Trying all 2ⁿ assignments is exponential. The forced propagation of colours decides in O(V + E).

Core idea

color[v] = −1 initially. For each uncoloured vertex, colour it 0 and BFS/DFS: for each neighbour, if uncoloured give it the opposite colour; if coloured with the same colour as the current vertex, return false.

How it works
  1. Fill color with −1.
  2. For every uncoloured vertex: set colour 0 and traverse.
  3. Neighbour uncoloured → opposite colour; coloured the same → not bipartite.
  4. If no conflict in any component → bipartite.

Implicit graphs: BFS over states

Frequently asked
When to useYou have a start state, a goal state and moves, and you need the fewest moves.
Detect it"minimum transformations / mutations / turns" · "word ladder" · "open the lock" · "sliding puzzle" · "perfect squares" · "jumps to reach home".
Intuition

Draw every possible configuration as a dot and join two dots if one move turns one into the other. You never have to draw the whole picture: from any state you can generate its neighbours by applying the moves. "Fewest moves" is then a shortest path in an unweighted graph, which is BFS.

Brute force → optimised

Trying every sequence of moves is exponential. BFS visits each distinct state once, so the cost is the number of reachable states times the cost of generating neighbours.

Core idea

Encode a state (string, tuple, integer). neighbors(state) yields states reachable in one move. BFS from the start with a visited set, level by level; the level number when you first see the goal is the answer. Skip forbidden states (deadends).

How it works
  1. Pick a hashable state representation.
  2. Write neighbors(state) (change one letter, turn a wheel, slide a tile).
  3. BFS with a visited set (initially including forbidden states).
  4. Return the number of levels when the goal is dequeued; −1 if the queue empties.

Border-first search: think in reverse

Secondary
When to useA region counts (or not) depending on whether it touches the border or can reach a special edge.
Detect it"surrounded regions" · "number of enclaves" · "closed islands" · "Pacific Atlantic water flow" · "cells that can reach both oceans".
Intuition

To find the ponds that are completely enclosed, do not test every pond. Instead, find the water that is connected to the outside (the border) and mark it. Whatever water is left unmarked cannot reach the border, so it is enclosed. Searching from the safe cells inward costs one traversal instead of one per region.

Brute force → optimised

Run a search from every cell to see if it reaches the border: O((mn)²). Searching once from all border cells and marking what they reach is O(m·n).

Core idea

Seed a DFS/BFS from every qualifying border cell and mark everything reachable. Then one scan: unmarked cells are the answer (flip them, count them). For two-sided questions (Pacific and Atlantic) run one reverse search per ocean and intersect.

How it works
  1. Collect border cells that satisfy the condition (the Os, the land).
  2. DFS/BFS from each, marking reachable cells safe.
  3. Scan the grid: unmarked qualifying cells are enclosed.
  4. Flip, count or intersect as the problem asks.

Self-test

Answer in your head first, then open the question to reveal the answer.

Why mark a vertex visited when you enqueue it in BFS?

Otherwise several neighbours can enqueue the same vertex before it is processed, growing the queue and (with weights or counts) giving wrong results.

Why does BFS find shortest paths in unweighted graphs?

It processes vertices in order of distance from the source, so the first time a vertex is reached is by a path with the fewest edges.

Why does directed cycle detection need three colours?

A visited vertex may be finished (harmless cross or forward edge) or still on the current path (back edge = cycle). Only the grey state signals a cycle.

What is the time complexity of DFS or BFS over an adjacency list?

O(V + E): each vertex is processed once and each edge is examined once (twice if undirected).

How does multi-source BFS beat running BFS from each source?

All sources start in the same queue at distance 0, so each cell is reached by the nearest source in one pass: O(V + E) instead of O(sources × (V + E)).

When is a graph bipartite?

Exactly when it contains no odd-length cycle; BFS or DFS two-colouring detects a violation as an edge joining two vertices of the same colour.

How do you count connected components?

Loop over all vertices; each time you meet an unvisited one, increment the counter and traverse its whole component.

Why search from the border in Surrounded Regions?

The border-connected Os are exactly the safe ones; marking them with one traversal leaves the enclosed regions unmarked, avoiding a separate search per region.

Study plan

  1. Day 1: representation and DFS: build adjacency lists, count components, clone a graph.
  2. Day 2: BFS shortest path on graphs and grids; write the template from memory.
  3. Day 3: grid problems: islands, max area, flood fill; then multi-source BFS (rotting oranges, 01 matrix).
  4. Day 4: cycle detection and course schedule; bipartite checks.
  5. Day 5: implicit graphs: word ladder, open the lock, perfect squares.
  6. Day 6: border-first problems and a mixed review; for each problem name the vertices, edges and traversal aloud.

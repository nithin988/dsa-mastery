Topic 04

Linked Lists — Pattern Guide

Linked lists test whether you can manage pointers without losing nodes. This guide covers the dummy node, reversal, fast and slow pointers, merging, the runner gap, split-reverse-merge, two-chain rewiring and LRU design, each with the intuition, a step-through animation that shows the arrows moving, Java and Python code, and a ladder of LeetCode problems.

For each section: read Detect and Intuition, play the animation, then try to write the skeleton from memory before opening the code. Finish by solving the problem ladder in order.

The mindset

A singly linked list gives you one thing: follow next. Everything else is pointer bookkeeping. Three habits solve most problems: use a dummy head so the first node is not special, save next before you overwrite it, and draw the pointers before and after each change. Two-pointer tricks (fast/slow, a fixed gap) replace the random access you do not have.

Ask these questions on every linked-list problem:

  • Can the head change? → add a dummy node.
  • Do I need to go backwards or compare from both ends? → reverse a half, or use a stack.
  • Is there a cycle, or a position counted from the end? → fast/slow or a fixed gap.
  • Am I about to overwrite next? → save it in a temporary first.
  • Must I keep O(1) space? → rewire nodes in place instead of copying values.

Pointer basics and the dummy node

🔥 Frequently asked
When to useYou insert, delete or rebuild nodes, especially when the head itself might change.
Detect it"remove all nodes with value" · "delete duplicates" · "insert into a sorted list" · any code with if (head == null) special cases.
Intuition

A linked list is a treasure hunt: each node only knows where the next clue is. To remove a node you must stand on the node before it and re-point its arrow past the target. If the target can be the very first node, there is nobody to stand on: so put a fake node (dummy) in front and the first node is no longer special.

Brute force → optimised

Without a dummy you write one branch for "head needs removing" and another for the middle, and bugs hide in the first. With a dummy there is a single loop and dummy.next is always the answer.

Core idea

Keep prev on the node before the candidate. If prev.next must go, do prev.next = prev.next.next and do not move prev; otherwise advance prev.

How it works
  1. dummy = new ListNode(0, head), prev = dummy.
  2. While prev.next != null: look at prev.next.
  3. If it matches, unlink it. Otherwise prev = prev.next.
  4. Return dummy.next.

Skeleton

remove all nodes with a given value

ListNode dummy = new ListNode(0, head), prev = dummy;
while (prev.next != null) {
    if (prev.next.val == val) prev.next = prev.next.next;   // unlink, stay put
    else prev = prev.next;
}
return dummy.next;
dummy = ListNode(0, head)
prev = dummy
while prev.next:
    if prev.next.val == val:
        prev.next = prev.next.next          # unlink, stay put
    else:
        prev = prev.next
return dummy.next
Skeleton

insert after a node (order of the two assignments matters)

ListNode node = new ListNode(x);
node.next = prev.next;     // 1) new node points to the old next FIRST
prev.next = node;          // 2) then the previous node points to the new node
node = ListNode(x)
node.next = prev.next      # 1) new node points to the old next FIRST
prev.next = node           # 2) then the previous node points to the new node
⏱ Complexity — O(n) time, O(1) space.
Traps to avoid
  • Assigning prev.next = node before node.next = prev.next loses the rest of the list.
  • After deleting, do not advance prev: the new prev.next has not been examined.
  • Check null before dereferencing: cur.next.next needs cur.next != null.
  • Sorted duplicates II (remove every value that repeats): skip the whole run and link prev past it.
Variants and follow-ups
  • Delete a node given only that node (LC 237): copy the next node's value into it and skip the next node.
  • Remove duplicates from a sorted list: compare cur with cur.next.
  • Insert into a sorted list: find the last node smaller than the value.
When NOT to use

When you need random access by index (use an array), or the structure never changes.

Reversing a linked list

🔥 Frequently asked
When to useReverse all of a list, a sub-range, or groups of k; or you need to read the list backwards without extra memory.
Detect it"reverse" · "reverse between positions" · "reverse in groups of k" · "swap pairs" · palindrome and reorder problems (as a step).
Intuition

A line of people each pointing at the next. To reverse it, walk along and make every person point at the one behind them instead. You need three fingers: one on the person you are fixing (cur), one on the person behind (prev), and one remembering who was next (nxt) before you break that link.

Brute force → optimised

Copy values into an array and rewrite them: O(n) extra space. Re-pointing arrows in place needs only three pointers: O(1) space.

Core idea

Iterate once. For each node save nxt = cur.next, set cur.next = prev, then slide prev = cur, cur = nxt. When cur is null, prev is the new head.

How it works
  1. prev = null, cur = head.
  2. Save nxt = cur.next.
  3. Flip: cur.next = prev.
  4. Advance: prev = cur, cur = nxt. Repeat; return prev.

Skeleton

iterative and recursive reversal

// iterative: O(n) time, O(1) space
ListNode reverse(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode nxt = cur.next;
        cur.next = prev;
        prev = cur;
        cur = nxt;
    }
    return prev;
}
// recursive: O(n) time, O(n) stack
ListNode reverseRec(ListNode head) {
    if (head == null || head.next == null) return head;
    ListNode newHead = reverseRec(head.next);
    head.next.next = head;      // the node after me now points back to me
    head.next = null;
    return newHead;
}
def reverse(head):                    # iterative: O(n) time, O(1) space
    prev, cur = None, head
    while cur:
        nxt = cur.next
        cur.next = prev
        prev, cur = cur, nxt
    return prev

def reverse_rec(head):                # recursive: O(n) time, O(n) stack
    if not head or not head.next:
        return head
    new_head = reverse_rec(head.next)
    head.next.next = head             # the node after me now points back to me
    head.next = None
    return new_head
Skeleton

reverse positions left..right (head insertion)

ListNode dummy = new ListNode(0, head), prev = dummy;
for (int i = 1; i < left; i++) prev = prev.next;      // node before the range
ListNode cur = prev.next;
for (int i = 0; i < right - left; i++) {
    ListNode nxt = cur.next;
    cur.next = nxt.next;       // detach nxt
    nxt.next = prev.next;      // put it at the front of the range
    prev.next = nxt;
}
return dummy.next;
dummy = ListNode(0, head)
prev = dummy
for _ in range(left - 1):
    prev = prev.next                  # node before the range
cur = prev.next
for _ in range(right - left):
    nxt = cur.next
    cur.next = nxt.next               # detach nxt
    nxt.next = prev.next              # put it at the front of the range
    prev.next = nxt
return dummy.next
⏱ Complexity — O(n) time; O(1) space iteratively, O(n) stack recursively.
Traps to avoid
  • Save cur.next before overwriting it, or the rest of the list is lost.
  • The reversed list's tail must end with null (head.next = null in the recursive version).
  • Reverse-in-groups-of-k: check that k nodes remain before reversing, and reconnect the group's old head to the next group's new head.
  • Use a dummy node for sub-range reversal so left = 1 works.
Variants and follow-ups
  • Reverse nodes in k-group: reverse each full block, link blocks together.
  • Swap nodes in pairs: reversal with k = 2.
  • Reverse a list in two stacks or recursion only when space is allowed.
When NOT to use

When the list is doubly linked (swap prev and next pointers instead) or you only need to read values (use an array or recursion).

Fast and slow pointers (middle and cycles)

🔥 Frequently asked
When to useFind the middle, detect a cycle, find where a cycle begins, or detect repetition in a sequence.
Detect it"middle of the list" · "has a cycle" · "where does the cycle begin" · "happy number" · "find the duplicate".
Intuition

Two runners on a track. If the track is a straight line, the fast runner reaches the end first, and when it does the slow one is exactly halfway. If the track is a loop, the fast runner keeps lapping and must eventually catch the slow runner from behind, because it gains one step per move.

Brute force → optimised

Store every visited node in a hash set to detect a repeat: O(n) extra space. Floyd's tortoise and hare uses two pointers and O(1) space.

Core idea

slow moves 1, fast moves 2. If fast reaches null: no cycle, and slow is the middle. If they meet: a cycle. To find its start, restart one pointer at the head and move both one step at a time; they meet at the cycle's first node.

How it works
  1. slow = fast = head.
  2. While fast != null && fast.next != null: slow = slow.next, fast = fast.next.next.
  3. If slow == fast: a cycle. Reset slow = head; advance both by 1 until equal; that node is the cycle start.
  4. If the loop ends, no cycle. slow is the middle (the second middle for even length).

Skeleton

detect a cycle and find its start

ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) {                  // cycle found
        slow = head;
        while (slow != fast) { slow = slow.next; fast = fast.next; }
        return slow;                     // first node of the cycle
    }
}
return null;                             // no cycle
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    if slow is fast:                     # cycle found
        slow = head
        while slow is not fast:
            slow = slow.next
            fast = fast.next
        return slow                      # first node of the cycle
return None                              # no cycle
Skeleton

middle of the list

ListNode slow = head, fast = head;
while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
return slow;        // for even length this is the second middle
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
return slow         # for even length this is the second middle
⏱ Complexity — O(n) time, O(1) space.
Traps to avoid
  • Loop condition must check both fast != null and fast.next != null before fast.next.next.
  • Compare nodes with == / is, not values: duplicate values are normal.
  • For even-length lists decide which middle you need; start fast = head.next to get the first middle.
  • Floyd needs a successor function, not necessarily a list: it also works on x → f(x) sequences.
Variants and follow-ups
  • Happy number: the digit-square sequence either reaches 1 or enters a cycle.
  • Find the duplicate in an array of n+1 numbers in 1..n: treat i → a[i] as a linked list with a cycle.
  • Cycle length: after meeting, walk one pointer around until it returns.
When NOT to use

When extra memory is allowed and clarity matters more (a HashSet of visited nodes is simpler), or the structure is a tree or DAG.

Merging and sorting lists

🔥 Frequently asked
When to useCombine sorted lists, or sort a list efficiently.
Detect it"merge two sorted lists" · "merge k sorted lists" · "sort a linked list" · "insertion sort list".
Intuition

Two queues of people already in height order, merging into one line at a door: look at the two people at the front of each queue and let the shorter one through. You never need to look past the fronts, and you reuse the people (nodes) without copying.

Brute force → optimised

Dump all values into an array, sort and rebuild: O(n log n) time and O(n) extra space. Merging sorted lists directly reuses nodes in O(n) time and O(1) space.

Core idea

Keep a tail on a dummy node. Compare the two heads, link the smaller to tail, advance that list and tail. When one list ends, attach the other in one step. Merge sort on a list = split at the middle, sort both halves, merge.

How it works
  1. dummy = new ListNode(), tail = dummy.
  2. While both lists are non-empty: link the smaller head to tail; advance that list and tail.
  3. tail.next = (a != null) ? a : b.
  4. Return dummy.next. For k lists use a min-heap of heads or merge pairs (divide and conquer).

ListNode dummy = new ListNode(), tail = dummy;

Skeleton

merge sort a list (split at the middle, sort, merge)

ListNode sortList(ListNode head) {
    if (head == null || head.next == null) return head;
    ListNode slow = head, fast = head.next;              // fast starts one ahead: slow ends at the first half's tail
    while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
    ListNode mid = slow.next;
    slow.next = null;                                    // cut into two lists
    return merge(sortList(head), sortList(mid));
}
def sort_list(head):
    if not head or not head.next:
        return head
    slow, fast = head, head.next                         # slow ends at the first half's tail
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
    mid, slow.next = slow.next, None                     # cut into two lists
    return merge(sort_list(head), sort_list(mid))
Skeleton

merge k sorted lists with a min-heap

PriorityQueue<ListNode> pq = new PriorityQueue<>((x, y) -> x.val - y.val);
for (ListNode l : lists) if (l != null) pq.add(l);
ListNode dummy = new ListNode(), tail = dummy;
while (!pq.isEmpty()) {
    ListNode n = pq.poll();
    tail.next = n; tail = n;
    if (n.next != null) pq.add(n.next);
}
return dummy.next;
import heapq
heap = [(l.val, i, l) for i, l in enumerate(lists) if l]   # i breaks ties (nodes are not comparable)
heapq.heapify(heap)
dummy = tail = ListNode()
while heap:
    _, i, n = heapq.heappop(heap)
    tail.next = n
    tail = n
    if n.next:
        heapq.heappush(heap, (n.next.val, i, n.next))
return dummy.next
⏱ Complexity — Merge two: O(n + m) time, O(1) space. Sort list: O(n log n) time, O(log n) stack. Merge k: O(N log k) with a heap.
Traps to avoid
  • Use <= when comparing to keep the merge stable.
  • Cut the list (slow.next = null) before recursing, or the halves overlap forever.
  • Python heaps compare tuples: add an index tiebreaker, because ListNode objects are not orderable.
  • Do not forget tail.next = remaining; one list usually has nodes left.
Variants and follow-ups
  • Merge k lists by pairs (divide and conquer): O(N log k) with O(1) extra space.
  • Insertion sort on a list: O(n²) but simple.
  • Merge in place into the first array (LC 88 uses the back-to-front trick).
When NOT to use

Unsorted inputs (sort first), or when a random-access array with a built-in sort is allowed.

Runner gap: nth from end, intersection, rotate

🔥 Frequently asked
When to useYou need the kth node from the end, a position relative to the tail, or the node where two lists join.
Detect it"remove the nth node from the end" · "intersection of two lists" · "rotate list by k" · "delete the middle".
Intuition

Two people walking with a rope of fixed length between them. When the front person reaches the end, the rear person stands exactly that rope-length from the end. You learn a position counted from the back while walking only once from the front.

Brute force → optimised

Walk once to count the length, then walk again to length − n: two passes. A fixed gap between two pointers finds it in one pass.

Core idea

Advance fast n steps ahead, then move fast and slow together. When fast is on the last node, slow is right before the node to remove (use a dummy head so removing the first node works).

How it works
  1. Dummy head; slow = fast = dummy.
  2. Move fast forward n times.
  3. Move both until fast.next == null.
  4. slow.next = slow.next.next; return dummy.next.

Skeleton

remove the nth node from the end

ListNode dummy = new ListNode(0, head), slow = dummy, fast = dummy;
for (int i = 0; i < n; i++) fast = fast.next;            // build the gap
while (fast.next != null) { fast = fast.next; slow = slow.next; }
slow.next = slow.next.next;                              // delete
return dummy.next;
dummy = ListNode(0, head)
slow = fast = dummy
for _ in range(n):
    fast = fast.next                                     # build the gap
while fast.next:
    fast, slow = fast.next, slow.next
slow.next = slow.next.next                               # delete
return dummy.next
Skeleton

intersection of two lists (switch heads at the end)

ListNode a = headA, b = headB;
while (a != b) {
    a = (a == null) ? headB : a.next;     // after A ends, continue down B
    b = (b == null) ? headA : b.next;     // after B ends, continue down A
}
return a;                                 // intersection node, or null if none
a, b = headA, headB
while a is not b:
    a = headB if a is None else a.next    # after A ends, continue down B
    b = headA if b is None else b.next    # after B ends, continue down A
return a                                  # intersection node, or None if none
⏱ Complexity — O(n) time, O(1) space.
Traps to avoid
  • Without a dummy head, deleting the first node (n equals the length) crashes.
  • Stop when fast.next == null, not fast == null, or slow lands on the target instead of before it.
  • Intersection compares node identity, not values.
  • Rotate by k: take k % length, find the new tail at length − k − 1, cut and re-attach.
Variants and follow-ups
  • Rotate list: make the list circular, then break it at length − k.
  • Swap the kth node from the start with the kth from the end: two pointers and a swap of values.
  • Delete the middle node: fast and slow with prev.
When NOT to use

When the length is already known (index directly) or the list is doubly linked with a tail pointer (walk back).

Split, reverse, merge (palindrome and reorder)

🧊 Secondary
When to useYou must compare the front of the list with the back, or interleave front and back nodes, without extra space.
Detect it"palindrome linked list" · "reorder list L0→Ln→L1→Ln−1" · "twin sum" · "compare first half with second half".
Intuition

You cannot walk a singly linked list backwards. So fold it like a sheet of paper: find the middle, flip the second half so it runs backwards, and now both halves can be walked forward at the same time, meeting at the fold.

Brute force → optimised

Copy values to an array and use two indices: O(n) time and O(n) space. Splitting and reversing in place keeps the extra space at O(1).

Core idea

Three steps you already know: (1) fast/slow to find the middle, (2) reverse the second half, (3) walk both halves together to compare (palindrome) or interleave (reorder).

How it works
  1. Fast/slow: stop with slow at the end of the first half.
  2. second = reverse(slow.next); cut with slow.next = null if you need two lists.
  3. Walk p over the first half and q over the reversed second half together.
  4. Compare values, or alternate nodes (a.next = b; b.next = aNext).

⏱ Complexity — O(n) time, O(1) extra space.
Traps to avoid
  • Which middle? Use fast.next != null && fast.next.next != null so slow is the end of the first half (and the exact middle for odd length).
  • Cut the list before interleaving or you create a cycle.
  • Palindrome compare loops over the shorter (reversed) half; the middle node of odd lists is ignored.
  • Mention restoring the list if mutation is not allowed.
Variants and follow-ups
  • Maximum twin sum: same reversed-half walk, tracking the max pair sum.
  • Add Two Numbers II (digits not reversed): reverse both, add, reverse back (or use stacks).
When NOT to use

When extra O(n) memory is fine (an array copy is simpler) or the list is doubly linked (compare from both ends directly).

Rearranging and arithmetic with two chains

🧊 Secondary
When to useAdd numbers digit by digit, or split nodes into groups and join the groups.
Detect it"add two numbers" · "odd even linked list" · "partition list around x" · "split into parts".
Intuition

Sorting laundry into two baskets while walking along the list: each node goes onto the end of one of two chains (using a tail pointer for each). At the end you hang the second chain on the tail of the first. For addition, walk both lists together doing grade-school addition with a carry.

Brute force → optimised

Copy values into arrays, rearrange, rebuild: O(n) extra space. Rewiring nodes keeps O(1) extra space.

Core idea

Create one dummy head and one tail pointer per output chain. Append each node to the right chain, finish by terminating the last chain (tail.next = null) and linking chain A to chain B.

How it works
  1. Make dummy heads and tails for each output chain.
  2. For each node decide its chain and append it: tail.next = node; tail = node.
  3. Terminate the last chain with null to avoid cycles.
  4. Link the first chain's tail to the second chain's dummy head .next.

Traps to avoid
  • Forgetting g.next = null after partitioning leaves a cycle or stale tail.

When values (not nodes) can be moved freely and extra memory is acceptable.

Doubly linked list + hash map (LRU design)

🔥 Frequently asked
When to useYou need O(1) lookup and O(1) reordering or removal by recency or frequency.
Detect it"LRU cache" · "LFU cache" · "browser history" · "copy a list with random pointers" · "O(1) get and put with eviction".
Intuition

A stack of papers on a desk plus an index card box. The box tells you in O(1) where any paper is (hash map). Pulling a paper out of the middle and putting it on top is O(1) only if each paper knows its neighbours (doubly linked list). The oldest paper sits at the bottom, ready to be thrown away.

Brute force → optimised

A plain list needs O(n) to find a key and O(n) to move it. A map alone has no order. Combining both gives O(1) for every operation.

Core idea

Hash map key → node for lookup; doubly linked list ordered from most recent (front) to least recent (back). Dummy head and tail nodes remove all null checks when linking and unlinking.

How it works
  1. get(k): if missing return −1; else unlink the node, put it at the front, return the value.
  2. put(k, v): if present, update and move to front.
  3. If new and the cache is full, remove tail.prev (the LRU) from list and map.
  4. Insert the new node at the front and add it to the map.

Skeleton

LRU cache (Java, manual doubly linked list)

class LRUCache {
    class Node { int k, v; Node prev, next; Node(int k, int v) { this.k = k; this.v = v; } }
    Map<Integer, Node> map = new HashMap<>();
    Node head = new Node(0, 0), tail = new Node(0, 0);   // dummy sentinels
    int cap;
    LRUCache(int cap) { this.cap = cap; head.next = tail; tail.prev = head; }

    int get(int k) {
        Node n = map.get(k);
        if (n == null) return -1;
        unlink(n); addFront(n);
        return n.v;
    }
    void put(int k, int v) {
        Node n = map.get(k);
        if (n != null) { n.v = v; unlink(n); addFront(n); return; }
        if (map.size() == cap) { Node lru = tail.prev; unlink(lru); map.remove(lru.k); }
        n = new Node(k, v); map.put(k, n); addFront(n);
    }
    void unlink(Node n) { n.prev.next = n.next; n.next.prev = n.prev; }
    void addFront(Node n) { n.next = head.next; n.prev = head; head.next.prev = n; head.next = n; }
}
class Node:
    def __init__(self, k=0, v=0):
        self.k, self.v, self.prev, self.next = k, v, None, None

class LRUCache:
    def __init__(self, cap):
        self.cap, self.map = cap, {}
        self.head, self.tail = Node(), Node()            # dummy sentinels
        self.head.next, self.tail.prev = self.tail, self.head

    def _unlink(self, n):
        n.prev.next, n.next.prev = n.next, n.prev

    def _add_front(self, n):
        n.next, n.prev = self.head.next, self.head
        self.head.next.prev = n
        self.head.next = n

    def get(self, k):
        n = self.map.get(k)
        if not n:
            return -1
        self._unlink(n)
        self._add_front(n)
        return n.v

    def put(self, k, v):
        n = self.map.get(k)
        if n:
            n.v = v
            self._unlink(n)
            self._add_front(n)
            return
        if len(self.map) == self.cap:
            lru = self.tail.prev
            self._unlink(lru)
            del self.map[lru.k]
        n = Node(k, v)
        self.map[k] = n
        self._add_front(n)
⏱ Complexity — O(1) time for get and put, O(capacity) space.
Traps to avoid
  • Store the key in each node so you can delete it from the map on eviction.
  • Update the existing node's value on a repeated put, and mark it most recent.
  • Unlink before relinking; order of the four pointer assignments matters.
  • In an interview, mention that LinkedHashMap (Java) / OrderedDict (Python) do this for you, then implement it by hand.
Variants and follow-ups
  • LFU cache: map of frequency → doubly linked list plus a minFreq pointer (LC 460).
  • Copy list with random pointer: map old node → new node, two passes (LC 138).
  • Browser history: doubly linked list (or two stacks).
When NOT to use

When eviction order is irrelevant (a plain HashMap) or capacity is tiny (a simple list may be enough).

Rule of thumb

draw three boxes before coding: before, after the first change, and the edge case (empty list, single node, head removed). If the head can change, a dummy node is almost always the right first line.

Self-test

Answer in your head first, then click to reveal.

Why use a dummy node?

It puts a real node in front of the head, so deleting or inserting at the head follows the same code as any other position, and dummy.next is always the answer.

In iterative reversal, what happens if you do not save cur.next first?

After cur.next = prev the link to the rest of the list is gone, so the remaining nodes are lost.

Why must the fast pointer's loop check fast.next too?

fast jumps two nodes; dereferencing fast.next.next when fast.next is null throws a null-pointer error.

Why do the slow pointer and fast pointer always meet in a cycle?

Once both are inside the loop, the gap shrinks by one each step (fast gains 1), so it must reach zero; the fast pointer cannot jump over the slow one.

How do you find the cycle start after the meeting?

Reset one pointer to the head and move both one step at a time. The distance from the head to the cycle start equals the distance from the meeting point to the start (mod the cycle length), so they meet at the start.

How do you get the kth node from the end in one pass?

Move fast k steps ahead, then move both pointers together; when fast reaches the end, slow is k nodes from the end.

Why does an LRU cache use a doubly linked list?

To unlink a node from the middle in O(1) you must reach its predecessor, which a singly linked list cannot do without a scan.

What is the space complexity of the recursive reversal?

O(n): each recursive call stays on the call stack until the end of the list is reached.

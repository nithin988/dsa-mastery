Topic 07

Recursion and Backtracking — Pattern Guide

Backtracking is a systematic way to try every possibility while abandoning dead ends early. This guide starts with recursion itself, then covers the choose / explore / un-choose template through subsets, combinations, permutations, duplicates, string partitions, grid search, N-Queens and pruning. Each pattern has the intuition, a step-through animation of the decision tree, Java and Python code, and a ladder of LeetCode problems.

The mindset

Backtracking is depth-first search over a tree of decisions: pick an option, explore everything it leads to, then undo it and pick the next. Three questions define every solution: what is a choice, what makes a partial answer invalid (prune), and when is it complete (record). Always append a *copy* of the path and always undo what you did.

Ask these questions before writing the recursion:

  • What is one decision? (pick an element, place a queen, cut the string here)
  • What state do I carry? (path, start index, used[], remaining, visited)
  • When is the path complete? (record a copy)
  • When can I abandon it early? (prune before recursing)
  • Does order matter, and can values repeat? → start index vs used[], sort and skip duplicates.

Recursion fundamentals: base case, trust and the call stack

🔥 Frequently asked
When to useA problem is defined in terms of a smaller version of itself.
Detect it"n! " · "power" · "reverse recursively" · "is it a power of two" · any definition with "the rest of the problem is the same but smaller".
Intuition

Russian dolls: to open the biggest doll, open the next smaller one inside it and so on until the tiniest solid doll (the base case). You do not need to simulate every doll in your head. Trust that the call on the smaller problem returns the right answer, and just do the small step that combines it with yours.

Brute force → optimised

Writing the loop for every depth of nesting is impossible for tree-shaped problems. Recursion lets the language manage the "to do later" list for you on the call stack.

Core idea

Every recursive function has three parts: a base case that stops, a smaller subproblem (progress toward the base case), and a combine step that builds the answer from the sub-answer.

How it works
  1. Write the base case first (smallest input, answer known).
  2. Express the answer for n using the answer for something smaller.
  3. Make sure every call moves toward the base case.
  4. Check the depth: each pending call uses stack space, so depth = O(space).

factorial and recursive reverse (base case + smaller problem)

int fact(int n) {
    if (n <= 1) return 1;                 // base case
    return n * fact(n - 1);               // smaller problem, then combine
}

void reverse(char[] s, int l, int r) {
    if (l >= r) return;                   // base case: nothing left to swap
    char t = s[l]; s[l] = s[r]; s[r] = t;
    reverse(s, l + 1, r - 1);             // the middle is a smaller copy of the same problem
}

    if (n <= 1) return 1;

    return memo[n] = climb(n - 1) + climb(n - 2);
}

⏱ Complexity — Time = (number of calls) × (work per call). Space = recursion depth (plus any memo).
Traps to avoid
  • Missing or wrong base case causes infinite recursion and a stack overflow.
  • The recursive call must make progress (n − 1, l + 1); otherwise it loops forever.
  • Java and Python have no tail-call optimisation: depth of ~10⁴–10⁵ can overflow. Convert to a loop or an explicit stack.
  • Overlapping subproblems (Fibonacci) blow up to O(2ⁿ): add memoisation.
Variants and follow-ups
  • Fast power: halve the exponent each call (depth log n).
  • Mutual recursion and recursion on trees (topic 09).
  • Recursion → iteration: an explicit stack mimics the call stack.
When NOT to use

When a simple loop is clearer and the depth could be huge.

Subsets: the choose / explore / un-choose template

🔥 Frequently asked
When to useGenerate all subsets, or decide for each element whether it is in or out.
Detect it"all subsets / power set" · "all possible" · "letter case permutations" · "partition into k groups" · "target sum with +/−".
Intuition

Picture a tree of decisions. At the root you have chosen nothing. Each step you add one more element from those not yet considered. Walking down is choose, recursing is explore, coming back up and removing the element is un-choose (backtrack). Because you undo every choice, the same path list is reused for the whole search.

Brute force → optimised

Generating subsets with bitmasks works for small n. Backtracking is the same 2ⁿ work but lets you prune early (stop going down when a constraint is already broken).

Core idea

dfs(start, path): record path; for i from start to n − 1: append a[i], dfs(i + 1), remove a[i]. Using start ensures each combination is generated in one order only.

How it works
  1. Record the current path (a copy!).
  2. For each i from start: choose a[i] (append).
  3. Explore dfs(i + 1, path).
  4. Un-choose (remove the last element) and try the next i.

// include or exclude each element
void dfs(int[] a, int i, List<Integer> path) {
    if (i == a.length) { res.add(new ArrayList<>(path)); return; }
    dfs(a, i + 1, path);                                 // exclude a[i]
    path.add(a[i]);
    dfs(a, i + 1, path);                                 // include a[i]

}

⏱ Complexity — O(n · 2ⁿ) time (2ⁿ subsets, each copied in O(n)), O(n) recursion depth.
Traps to avoid
  • Append a copy of path (new ArrayList<>(path) / path[:]), not the list itself.
  • Always undo the choice after the recursive call, or paths leak into each other.
  • Pass i + 1 (not start + 1) so elements are not reused or reordered.
  • Pruning belongs before the recursive call (check the constraint, then choose).
Variants and follow-ups
  • Letter case permutation: two branches only at letters.
  • Target sum / partition to k equal subsets: include/exclude with a running sum and pruning.
  • Subsets of size k = combinations (next pattern).
When NOT to use

When the number of valid results is exponential but you only need a count or an optimum: use DP instead.

Combinations and combination sum

🔥 Frequently asked
When to useChoose k items, or any items whose sum meets a target, where order does not matter.
Detect it"combinations of k numbers" · "combination sum" · "letter combinations of a phone number" · "choose items to reach a total".
Intuition

Order does not matter for a combination, so impose one: only ever pick items at or after the one you took last. That removes the permutations of the same set without checking anything. Add pruning: if the candidate is already larger than what is left, stop (and, in a sorted list, so is everything after it).

Brute force → optimised

Generate all subsets and filter by sum: O(2ⁿ) work even when most are hopeless. Pruning cuts whole branches as soon as the remaining target is exceeded.

Core idea

Sort candidates. dfs(start, remaining, path): if remaining == 0 record; for i ≥ start: if c[i] > remaining break; choose c[i]; recurse with start = i (reuse allowed) or i + 1 (each once); un-choose.

How it works
  1. Sort the candidates (enables the early break).
  2. Base case: remaining == 0 → record a copy.
  3. Loop i from start; break when c[i] > remaining.
  4. Recurse with i (unlimited reuse) or i + 1 (single use).

Traps to avoid
  • Use i for reusable candidates and i + 1 for single-use ones.
  • Without sorting, the break prune is wrong (use continue instead).

  • Number of ways (not the lists): use DP / unbounded knapsack instead.
When NOT to use

When only the count of combinations is needed (DP is polynomial) or the target is huge.

Permutations: choose any unused element

🔥 Frequently asked
When to useArrange all items in every possible order.
Detect it"all permutations" · "all arrangements" · "next / k-th permutation" · "beautiful arrangement".
Intuition

Filling n seats one by one: for seat 1 you may pick anyone, for seat 2 anyone who is not already seated, and so on. The used array is the list of people already seated. When all seats are filled, record the arrangement; then un-seat the last person and try someone else.

Brute force → optimised

Trying all n^n sequences and rejecting repeats is wasteful. Tracking used ensures only n! valid sequences are ever generated.

Core idea

dfs(path): if path.size() == n record; for each index i not used: mark used, append, recurse, remove, unmark. A swap-based variant permutes the array in place.

How it works
  1. Base case: path is full → record a copy.
  2. For each element not used: mark it used and append.
  3. Recurse for the next position.
  4. Backtrack: remove it and mark unused.

  • Beautiful arrangement: permutations with a divisibility check as pruning.
  • Permutation sequence: compute the k-th directly with factorials.
  • Permutations with duplicates: sort and skip repeats (next pattern).
When NOT to use

When you need only the k-th or next permutation, or the number of permutations (use math).

Handling duplicates: sort and skip

🔥 Frequently asked
When to useThe input has repeated values and the output must not contain duplicate subsets, permutations or combinations.
Detect it"Subsets II" · "Permutations II" · "Combination Sum II" · "unique combinations" · "no duplicate sets".
Intuition

If two cards both show a 2, choosing "the first 2" and then "the second 2" gives the same hand as the reverse. To avoid that, make equal cards line up (sort) and add a rule: at any one position in the decision tree, you may use a given value only once as a choice. The second 2 can still be used deeper in the recursion (after the first 2 was chosen).

Brute force → optimised

Generate everything and remove duplicates with a set: correct but wastes time and memory. Skipping at the source never creates the duplicates.

Core idea

Sort the array. In the loop at a given level, if (i > start && a[i] == a[i − 1]) continue;. For permutations use used[] and skip when a[i] == a[i − 1] && !used[i − 1].

How it works
  1. Sort so equal values are adjacent.
  2. Within one loop level, skip a[i] if it equals a[i − 1] and i > start (the first of the run was already tried at this level).
  3. Permutations: skip a[i] if a[i − 1] is equal and not currently used.
  4. Everything else is the normal template.

Traps to avoid
  • You must sort first; the skip rule relies on equal values being adjacent.
  • i > start (not i > 0) for subsets and combinations; i > 0 with the !used[i − 1] condition for permutations.

  • Letter tile possibilities: count letters and branch over distinct letters.
When NOT to use

Strings: partitions, cuts and letter choices

🔥 Frequently asked
When to useSplit a string into pieces that each satisfy a rule, or build a string from per-position choices.
Detect it"palindrome partitioning" · "restore IP addresses" · "word break II" · "letter combinations" · "concatenated string with unique characters".
Intuition

Cutting a loaf into slices where every slice must be acceptable. Stand at the current cut position and try every possible next slice: if the slice is valid, take it and continue from where it ends. If you reach the end of the loaf, the slices so far are an answer.

Brute force → optimised

Try every set of cut positions (2ⁿ⁻¹) and check each piece afterwards. Checking each piece as soon as it is formed rejects bad cuts early.

Core idea

dfs(start, path): if start == n record path. For end in start..n−1: piece = s[start..end]; if valid, append, dfs(end + 1), remove.

How it works
  1. Base case: start == n → record the partition.
  2. Loop end from start to n − 1.
  3. If s[start..end] is valid (palindrome, number 0–255, dictionary word), choose it.
  4. Recurse from end + 1; then un-choose.

Grid and path search with visited marking

🔥 Frequently asked
When to useFind a path through a grid or board where cells cannot be reused within one path.
Detect it"word search" · "path with maximum gold" · "unique paths III" · "can the word be formed from adjacent cells".
Intuition

Exploring a maze with a ball of thread: leave a mark where you have been so you do not walk in circles, and when a corridor dead-ends, walk back removing the mark so a different route can still pass through that cell. The un-marking is what makes it backtracking rather than a plain flood fill.

Brute force → optimised

Enumerating all paths blindly explodes. Matching the next letter at each step rejects almost every path immediately.

Core idea

For each start cell run dfs(r, c, k): fail on out-of-bounds, a visited cell or a mismatch; mark the cell; try 4 neighbours; unmark; return whether any succeeded.

How it works
  1. Try every cell as a start.
  2. dfs: if k == len(word) → success.
  3. Reject if out of bounds or board[r][c] != word[k].
  4. Mark visited (e.g. set to #), recurse in 4 directions, restore the cell, return the result.

boolean dfs(char[][] b, String w, int k, int r, int c) {
    if (k == w.length()) return true;
    if (r < 0 || c < 0 || r >= b.length || c >= b[0].length || b[r][c] != w.charAt(k)) return false;
    char t = b[r][c];
    b[r][c] = '#';                                            // mark visited
    boolean ok = dfs(b, w, k + 1, r + 1, c) || dfs(b, w, k + 1, r - 1, c)
              || dfs(b, w, k + 1, r, c + 1) || dfs(b, w, k + 1, r, c - 1);
    b[r][c] = t;                                              // un-mark (backtrack)
    return ok;
}
def exist(board, word):
    R, C = len(board), len(board[0])
    def dfs(r, c, k):
        if k == len(word):
            return True
        if not (0 <= r < R and 0 <= c < C) or board[r][c] != word[k]:
            return False
        t, board[r][c] = board[r][c], '#'                     # mark visited
        ok = (dfs(r + 1, c, k + 1) or dfs(r - 1, c, k + 1) or
              dfs(r, c + 1, k + 1) or dfs(r, c - 1, k + 1))
        board[r][c] = t                                       # un-mark (backtrack)
        return ok
    return any(dfs(r, c, 0) for r in range(R) for c in range(C))

Constraint search: N-Queens and Sudoku

🔥 Frequently asked
When to useFill a board so that every row, column or region obeys constraints.
Detect it"N-Queens" · "Sudoku solver" · "place pieces so none attack" · "fill the grid".
Intuition

Place one thing at a time in a fixed order (row by row). At each step only the options consistent with everything already placed are tried. If a row has no legal option, an earlier decision must have been wrong, so undo the previous placement and try its next option. Constant-time conflict checks (boolean arrays for columns and diagonals) keep it fast.

Brute force → optimised

Putting n queens anywhere is C(n², n) boards. One queen per row cuts it to nⁿ; rejecting conflicts immediately cuts it to a tiny fraction.

Core idea

dfs(row): if row == n record the board; for each column: if no conflict, place, dfs(row + 1), remove. Conflicts: col, row + col (anti-diagonal) and row − col (diagonal) each tracked in a set or boolean array.

How it works
  1. Row by row: for each column, test cols[c], d1[r + c], d2[r − c + n − 1].
  2. If safe: mark the three, place the queen, recurse to the next row.
  3. On return: unmark and remove.
  4. At row == n: record (or count) the solution.

        cols[c] = d1[r + c] = d2[r - c + n - 1] = true;          // place

def total_n_queens(n):
    cols, d1, d2 = set(), set(), set()
    def dfs(r):
        if r == n:
            return 1
        count = 0
        for c in range(n):
            if c in cols or r + c in d1 or r - c in d2:
                continue
            cols.add(c); d1.add(r + c); d2.add(r - c)            # place
            count += dfs(r + 1)
            cols.remove(c); d1.remove(r + c); d2.remove(r - c)   # remove
        return count
    return dfs(0)

boolean solve(char[][] b) {
    for (int r = 0; r < 9; r++) for (int c = 0; c < 9; c++) {
        if (b[r][c] != '.') continue;
        for (char d = '1'; d <= '9'; d++) {
            if (!ok(b, r, c, d)) continue;
            b[r][c] = d;
            if (solve(b)) return true;
            b[r][c] = '.';                                       // undo
        }
        return false;                                            // no digit fits: backtrack
    }
    return true;                                                 // no empty cell left
}

    for (int i = 0; i < 9; i++)
        if (b[r][i] == d || b[i][c] == d || b[r / 3 * 3 + i / 3][c / 3 * 3 + i % 3] == d) return false;
    return true;
}
def solve(b):
    for r in range(9):

  • N-Queens II: count only.
  • Bitmask version of N-Queens with three integers is the fastest.

When the constraint structure fits a polynomial algorithm (matching, DP).

Pruning and memoisation: generate only valid states

🧊 Secondary
When to useMost branches of the search tree are invalid, or the same sub-state is reached again and again.
Detect it"generate parentheses" · "remove invalid parentheses" · "word break" · "expression add operators" · "additive number".
Intuition

Instead of writing every possible string and then crossing out the bad ones, never write a letter that can only lead to a bad string. For parentheses: you may open a bracket while some are still unspent, but you may close one only if an open one is waiting. The tree contains only valid prefixes, so nothing is wasted. When the same sub-problem reappears (the same suffix of a string), remember its answer.

Brute force → optimised

Generating all 2^(2n) strings and filtering costs exponential time even for tiny answers. Pruned generation visits only the Catalan(n) valid results and their valid prefixes.

Core idea

Carry the state that defines validity (open, close, current sum, last operand) and check it before recursing. If dfs(state) can be reached by several paths, cache state → result (memoisation); this is the bridge to dynamic programming.

How it works
  1. Identify the invariant of a valid prefix (e.g. close ≤ open ≤ n).
  2. Only recurse into choices that keep the invariant.
  3. Record when the length (or goal) is reached.
  4. If states repeat, add a memo keyed by the state.

Self-test

Answer in your head first, then click to reveal.

Why do we append new ArrayList<>(path) instead of path when recording a result?

path is reused and mutated throughout the search; recording the same object would make every stored result end up empty or equal to the last path.

What is the difference between the subsets template and the permutations template?

Subsets use a start index so elements are picked in increasing order (order does not matter). Permutations loop over all indices and use a used array because order matters.

In Combination Sum, why recurse with i rather than i + 1?

The same candidate may be reused, so the next level may pick the same index again; i (not start) also keeps combinations in non-decreasing order.

How does if (i > start && a[i] == a[i − 1]) continue; prevent duplicates?

At one level it lets only the first element of a run of equal values be chosen, so identical branches are not created; later equal values can still be used deeper.

Why is un-marking the cell essential in Word Search?

A cell visited in a failed path must become available again for other paths. Without un-marking, valid words are missed.

Name the three conflict checks in N-Queens.

Column, diagonal (row − col) and anti-diagonal (row + col), each in an O(1) boolean array or set.

What does pruning change about the time complexity?

The worst case is usually unchanged, but whole subtrees are skipped, so real running time drops massively (for example only Catalan(n) parenthesis strings are visited).

When should backtracking become dynamic programming?

When you only need a count, a boolean or an optimum and the same sub-state is reached through many paths; cache by state (memoise) or fill a table.

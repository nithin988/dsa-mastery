Topic 03

Strings — Pattern Guide

Strings are arrays of characters with extra rules: immutability, small alphabets, and substring structure. This guide covers counting, two pointers, palindromes, windows, pattern matching, stack parsing, in-place edits and character tricks, each with the intuition, a step-through animation, Java and Python code, and a ladder of LeetCode problems.

The mindset

Almost every string problem becomes easy once you ask what it is really about: letter counts (hashing), symmetry (two pointers or a centre), a contiguous range (window), repeated structure (a border or a hash), or nesting (a stack). Because strings are immutable, also watch the hidden cost of building them: use StringBuilder / ''.join.

Ask these questions on every string problem:

  • Does order matter? If not, count characters. If yes, think pointers, window or stack.
  • Is the answer a substring (contiguous) or a subsequence? Substring → window or centre; subsequence → pointers or DP.
  • How big is the alphabet? 26 or 128 → a fixed array and O(1) space.
  • Is there nesting or a closing token? → stack.
  • Am I building the result with += in a loop? → switch to a builder.

Frequency counting and anagrams

🔥 Frequently asked
When to useOrder does not matter, only which characters appear and how often.
Detect it"anagram" · "permutation of" · "can construct" · "first unique character" · "isomorphic" · "group by letters".
Intuition

Two words are anagrams when they are built from the same bag of tiles. Do not sort the tiles; just count them. Add one for every tile in the first word, subtract one for every tile in the second, and the bag is balanced exactly when every count returns to zero.

Brute force → optimised

Sort both strings and compare: O(n log n). Counting into a 26-slot array is one pass: O(n) time, O(1) space.

Core idea

Replace the string by its letter-count signature. Two strings with the same signature are anagrams, and the signature can also be a hash key for grouping.

How it works
  1. Make int[26] count (or a map when characters are not just a–z).
  2. For each character of the first string do count[c - 'a']++; for the second do count[c - 'a']--.
  3. If any count is non-zero (or goes negative early), the answer is no.
  4. For grouping, use the sorted string or the 26-count tuple as the dictionary key.

Traps to avoid
  • Check lengths first; different lengths can never be anagrams.
  • count[c - 'a'] only works for lowercase a–z. For Unicode or mixed case use a HashMap.
  • For Group Anagrams, sorting each word costs O(k log k); the count key is O(k).
  • Isomorphic strings need a two-way mapping (a→b and b→a), not one.
Variants and follow-ups
  • Fixed-size window of an anagram check: slide the counts (LC 438, 567).
  • Ransom note: counts of the magazine must cover counts of the note.
  • Sort by frequency: bucket by count.
When NOT to use

When characters must stay in order (use two pointers or DP), or when only one specific position matters.

Two pointers on strings

🔥 Frequently asked
When to useChecking symmetry, reversing, or merging two strings position by position.
Detect it"palindrome" · "reverse in place" · "is subsequence" · "ignore case / non-alphanumeric" · "at most one deletion".
Intuition

Read a word from both ends toward the middle like closing a zipper. As long as the two teeth match, keep closing; the first mismatch tells you the answer. Characters that do not count (spaces, punctuation) are simply stepped over without comparing.

Brute force → optimised

Build the reversed string and compare: O(n) time but O(n) extra space and a second pass. Two pointers compare in place with O(1) space.

Core idea

l starts at the left, r at the right. Skip irrelevant characters, compare the relevant pair, move both inward, stop when they cross.

How it works
  1. l = 0, r = n − 1.
  2. While l < r: advance l past non-alphanumerics; retreat r past non-alphanumerics.
  3. Compare the two characters (lower-case). Mismatch → false.
  4. Move both inward. If the loop ends, it is a palindrome.

Expand around the centre (palindromic substrings)

🔥 Frequently asked
When to useFind the longest or count all palindromic substrings.
Detect it"longest palindromic substring" · "count palindromic substrings" · "palindrome that contains the middle".
Intuition

Drop a pebble in water: ripples spread outward symmetrically. A palindrome is a ripple pattern: from its centre, the left and right characters match at every distance. So instead of testing every substring, test every possible centre and let the ripple grow as long as both sides match.

Brute force → optimised

Check every substring for being a palindrome: O(n³). Expanding from each of the 2n − 1 centres costs O(n) each: O(n²) with O(1) space.

Core idea

A palindrome centre is either a character (odd length) or the gap between two characters (even length). For each centre expand l--, r++ while s[l] == s[r].

How it works
  1. For each i from 0 to n − 1, expand from (i, i) (odd) and (i, i + 1) (even).
  2. While l ≥ 0, r < n and s[l] == s[r], widen.
  3. Track the best (start, length) or add one to a counter for each successful expansion.
  4. Return the best substring or the count.

longest palindromic substring

int start = 0, best = 0;
for (int i = 0; i < s.length(); i++) {
    int len = Math.max(expand(s, i, i), expand(s, i, i + 1));
    if (len > best) { best = len; start = i - (len - 1) / 2; }

int expand(String s, int l, int r) {
    while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) { l--; r++; }
    return r - l - 1;                       // length of the palindrome found
}
def longest(s):
    def expand(l, r):
        while l >= 0 and r < len(s) and s[l] == s[r]:
            l -= 1
            r += 1
        return r - l - 1                    # length of the palindrome found
    start = best = 0
    for i in range(len(s)):
        length = max(expand(i, i), expand(i, i + 1))
        if length > best:
            best = length
            start = i - (length - 1) // 2
    return s[start:start + best]
⏱ Complexity — O(n²) time, O(1) space. Manacher's algorithm reaches O(n) but is rarely required.
Traps to avoid
  • Forget the even-length centres and "abba" fails.
  • Start index of the best palindrome is i − (len − 1) / 2 for both parities.
  • Return length as r − l − 1 after the loop has stepped one too far on each side.
  • Do not use a DP table when O(1) space is enough; DP is O(n²) space.
Variants and follow-ups
  • Count palindromic substrings: add 1 for every successful expansion.
  • Longest palindromic subsequence is a different problem (DP, topic 16).
  • Shortest palindrome by adding characters in front: KMP prefix function (pattern 5).
When NOT to use

When n is huge and O(n²) is too slow (use Manacher), or the problem is about subsequences rather than substrings.

Sliding window on strings

🔥 Frequently asked
When to useA contiguous substring must satisfy a condition about its letters.
Detect it"longest substring without repeating" · "at most K distinct" · "minimum window containing" · "replace at most k characters".
Intuition

An inchworm along the text. The head stretches right to take in letters; whenever the body breaks the rule, the tail pulls in until it is legal again. Neither end ever steps backwards, so every letter enters once and leaves once.

Brute force → optimised

Test every substring: O(n²) substrings × O(n) to check = O(n³). The window visits each position twice at most: O(n).

Core idea

Keep a count map for the window and a formed counter of how many requirements are satisfied. Expand r; while the window is valid (min-window) or invalid (longest), move l.

How it works
  1. Build need counts for the target (if any); have counts for the window; formed = 0.
  2. Expand r: add s[r], update have and formed.
  3. While the window is valid (or invalid, for "longest"): record the answer, drop s[l], l++.
  4. Return the best window.

String matching: KMP, Z and rolling hash

🧊 Secondary
When to useFind a pattern in a text in linear time, or reason about borders (prefix = suffix).
Detect it"first occurrence of" · "repeated substring pattern" · "longest happy prefix" · "shortest palindrome" · "duplicate substring of length L".
Intuition

While matching a long pattern you fail late: say 5 characters matched, the 6th differs. The naive method forgets everything and slides by one. But the 5 matched characters tell you something: if the start of the pattern also appears at their end, you can keep that overlap and continue without moving backwards in the text. The lps array stores that overlap for every prefix.

Brute force → optimised

Try every start position and compare: O(n·m). KMP precomputes the longest border of each pattern prefix and never moves the text pointer backwards: O(n + m).

Core idea

lps[i] = length of the longest proper prefix of p[0..i] that is also a suffix. On a mismatch after j matched characters, fall back to j = lps[j − 1] instead of restarting at 0. A rolling hash (Rabin–Karp) instead compares window hashes in O(1) per step.

How it works
  1. Build lps for the pattern: compare p[i] with p[len]; on a mismatch fall back len = lps[len − 1] until len = 0.
  2. Scan the text with index i and matched length j.
  3. On a match advance both; on a mismatch with j > 0 set j = lps[j − 1]; if j == m a match ends at i.
  4. Rolling hash: h = (h·B − out·B^m + in) mod M, then verify on hash equality.

int[] lps(String p) {
    int[] f = new int[p.length()];
    for (int i = 1, len = 0; i < p.length(); ) {
        if (p.charAt(i) == p.charAt(len)) f[i++] = ++len;
        else if (len > 0) len = f[len - 1];
        else f[i++] = 0;
    }
    return f;
}
int indexOf(String s, String p) {

        else if (j > 0) j = f[j - 1];

def lps(p):
    f, length, i = [0] * len(p), 0, 1
    while i < len(p):

            length += 1
            f[i] = length
            i += 1
        elif length:
            length = f[length - 1]
        else:
            f[i] = 0
            i += 1
    return f

def index_of(s, p):
    if not p:
        return 0
    f, j = lps(p), 0
    for i, c in enumerate(s):
        while j and c != p[j]:
            j = f[j - 1]
        if c == p[j]:
            j += 1
        if j == len(p):
            return i - j + 1
    return -1

        w = (w - ord(s[i - m]) * pw) % M              # remove the outgoing char
    w = (w * B + ord(c)) % M                           # add the incoming char
    if i >= m - 1 and w == h and s.startswith(p, i - m + 1):
        return i - m + 1
⏱ Complexity — KMP: O(n + m) time, O(m) space. Rabin–Karp: O(n + m) expected, O(n·m) worst case on hash collisions.
Traps to avoid
  • The fall-back is len = lps[len − 1], not len = 0 (and not len − 1).
  • Rolling hash: always verify on equality (collisions exist) and add M before the modulo when subtracting.
  • Empty pattern: return 0 by convention (LC 28).
  • In an interview, s.indexOf(p) is usually not allowed for the "implement strStr" question.
Variants and follow-ups
  • Repeated substring pattern: (s + s).indexOf(s, 1) != s.length(), or n % (n − lps[n−1]) == 0 with lps[n−1] > 0.
  • Z-function: z[i] = length of the longest match between s and s[i..]; pattern matching on p + '#' + s.
  • Binary search on length + rolling hash for the longest duplicate substring (LC 1044).
When NOT to use

When a built-in search is allowed and input is small, or when you need many patterns at once (use a trie or Aho–Corasick).

Stack-based parsing and decoding

🔥 Frequently asked
When to useThe string has brackets, nesting, or operators that must be resolved in order.
Detect it"valid parentheses" · "decode string" · "simplify path" · "remove adjacent duplicates" · "evaluate expression" · "calculator".
Intuition

Like opening nested Russian dolls: each opener makes you remember where you were, and each closer returns you to the most recent unfinished doll. "Most recent unfinished" is exactly what a stack gives you.

Brute force → optimised

Repeatedly scan and replace innermost brackets: O(n²). One left-to-right pass with a stack resolves everything in O(n).

Core idea

On an opening symbol, push the state you will need later (count, previous text, previous operator). On a closing symbol, pop it and combine it with what you have built inside.

How it works
  1. Scan left to right keeping the current text and number being built.
  2. [: push (count, text so far) and reset current text.
  3. ]: pop (count, prev); current = prev + current × count.
  4. Letter: append to the current text. Digit: extend the number.

Traps to avoid
  • Multi-digit counts (12[a]): build the number, do not read one digit.
  • Pop only after checking the stack is non-empty.

  • Calculator II (no parentheses): stack of numbers, apply * and / immediately, sum at the end.
  • Simplify path: split on /, push directories, pop on ...
  • Remove adjacent duplicates: push unless top equals current.
When NOT to use

When the structure is flat (no nesting), a simple loop or two pointers suffices.

In-place edits and simulation

🧊 Secondary
When to useTransform a string step by step with exact rules: compress, add, parse, reverse words.
Detect it"in place" · "compress" · "string to integer" · "add two numbers as strings" · "reverse words" · "zigzag".
Intuition

Think of a scribe copying a document onto the same page: the reading finger always runs ahead of the writing pen, so the pen never overwrites something it still needs. Two indices over the same array give you an in-place rewrite in a single pass.

Brute force → optimised

Build a new string with repeated concatenation: O(n²) copies. A single pass with a StringBuilder is O(n) time; a read/write pointer pair also gives O(1) extra space.

Core idea

Separate reading from writing. r scans input groups or tokens; w writes the result at the front. For arithmetic, process digits from the right with a carry.

How it works
  1. r = w = 0.
  2. Read one logical unit (a run of equal characters, a number, a word) starting at r and advance r past it.
  3. Write its encoded form at w and advance w.
  4. At the end, the answer is the first w characters.

When the transformation needs random access to later input (then build a new string instead of overwriting).

Character arithmetic and two-pass counting

🧊 Secondary
When to useThe alphabet is small and fixed, and you need order-aware answers (first, last, earliest).
Detect it"first unique character" · "maximum number of balloons" · "pangram" · "alien dictionary order" · "half of the string" · "minimum steps to make anagrams".
Intuition

A character is just a small integer. 'd' − 'a' = 3 is a free array index. Two passes are a classic combo: the first pass collects facts (counts), the second pass uses them in the original order (find the first with count 1).

Brute force → optimised

Nested loops comparing each character with all others: O(n²). One counting pass plus one scan: O(n).

Core idea

Map each character to a slot (c − 'a'), collect counts in pass one, then answer questions that depend on position in pass two. A bitmask can store "has this letter been seen" in one int.

How it works
  1. Allocate int[26] (or int[128] for ASCII).
  2. Pass 1: count with count[c − 'a']++.
  3. Pass 2: scan the original string and test count[c − 'a'] for the condition.
  4. For custom orders, build rank[c] from the given order and compare ranks.

  • c − 'a' is only valid for lowercase letters; guard or normalise otherwise.

  • Maximum number of balloons: counts divided by required copies, take the minimum.
  • Minimum steps to make anagrams: sum of positive differences in counts.
  • Caesar shift: (c − 'a' + k) % 26 + 'a'.
When NOT to use

Large or Unicode alphabets (use a hash map) or problems that need substrings rather than single characters.

Self-test

Answer in your head first, then click to reveal.

Why compare character counts instead of sorting to test anagrams?

Counting is O(n) time and O(1) space for a fixed alphabet; sorting is O(n log n).

Why must expand-around-centre try even-length centres as well?

A palindrome like "abba" has no single middle character; its centre is the gap between the two b's, so only the even expansion finds it.

In KMP, what does lps[i] mean and why does a mismatch use lps[len − 1]?

lps[i] is the longest proper prefix of p[0..i] that is also its suffix. After a mismatch the next-best partial match is the longest border of what has matched so far, which is lps[len − 1], so the text pointer never moves back.

What is the complexity of building a string with s += c in a loop of n iterations?

O(n²), because each concatenation copies the existing string. Use StringBuilder or ''.join for O(n).

Why is 3[a2[c]] naturally solved with a stack?

The innermost bracket must be finished first. A stack stores the unfinished outer context (count and text) and returns it in last-in, first-out order.

When does a window for "minimum window substring" count as valid?

When every required letter has at least its needed count inside the window, tracked by a formed counter that equals the number of distinct required letters.

Why is count[c − 'a'] risky?

It only works for lowercase a–z. Uppercase, digits or Unicode produce negative or out-of-range indices; use a larger array or a hash map.

Subsequence or substring: which problem allows a sliding window?

Substring (contiguous). Subsequence problems use two pointers (matching) or dynamic programming.
